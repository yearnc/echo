# 回响 Echo

一个**单 App 双模式**的社交媒体模拟器。同一块屏幕，两个世界：

- **回响模式** —— 你发一条帖子，周围会临时聚起一群像真人的网民：有人只看、有人点赞、有人接梗。你也可以自己配置固定住民，他们会自己醒来、用工具决定回不回、发不发帖，并记住你们聊过的事。**这里没有一个真实用户。**
- **清醒模式** —— 关掉所有虚拟反馈，只留**根据本机记录算出来的客观分析**（记录频率 / 互动构成 / AI 占比 / 情绪走向 / 时间分布）、数字关系反思、真实生活相册，以及价值重建练习（价值澄清、真实行动记录）。这里的数字不调用模型，也不评价你。

做这个东西的动机很简单：**「被回应」的感觉是可以被制造的**，而人在多大程度上依赖它，往往要等到它消失时才看得清。这个 APP 想把这件事摆到台面上，让你亲手开关一次。

> 项目背景：思政实践课题《数字时代大学生自我价值感的异化与重建》，同时是一部微电影的核心道具。旧住民的内置三幕脚本已经整套下线；拍摄仍可用「策划脚本」自建事件，见下文。

v3.10.0 是一次体验与稳定性补丁：

- **内置“说话方式”知识库**：`NetKnowledge` 收了一批**分寸**，不是网络梗大全——

  按帖子的语气 / 领域 / 关键词挑几条，注入到**用户消息**里（system 保持逐字节稳定，

- **文本式工具调用不再漏进私信**：DeepSeek 系模型有时把 `<｜｜DSML｜｜...>` 当普通

  工具调用**，并把标记洗干净；正文路径上再加一层清洗，双保险。
- **唤醒日志更像日志**：记下这一轮**实际调用了哪些工具**（翻记忆、发私信、发动态…），
  连续同名的只留一条；**十分钟内连续的 user_action 唤醒合并成一条**，
  用户连发几句不会再刷出好几条“有人叫了 TA”。合并只影响日志行，
  私信分段的幂等键仍然每轮独立。
- **编辑页收拢**：「人设」和「说话」合并成一张「编辑人设与说话方式」卡片，点开才算；

**桌宠（P3）**：形象独立于住民，素材从开源桌宠
[dsh-pet](https://github.com/PC2005-cloud/dsh-pet) 转出**全部 106 个动作**，
每个动作 48 帧**无损 WebP**（alpha 也走无损，不是动画 WebP：部分 ROM 会把
透明区画成黑框）。动作分六类：待机 1、转向 1、拖拽 1、点击回应 5、
走路 3、随机小动作 80（小动作 / 玩耍 / 吃什么 / 时节 / 文字），
外加原本属于事件的余额 6、碎碎念 3、工作状态 6——它们以低权重混进随机链，
106 个动作每个都抽得到。`assets/pet_frames/manifest.json` 是唯一清单，
帧文件名由它编号，Kotlin 和 Dart 都按这份认动作。

**两个窗口**：舞台窗从整帧裁到角色本体（约 100×105dp，`CENTER_CROP` 去掉透明边），
**接收触摸**；命中窗与舞台完全重合，拖拽和点击都落在这里。气泡仍是单独一层、
不可触摸，叠在角色身上、最多两行、宽度上限 190dp（约十四个字换行），逐字出现。

**漫游**：走路类动作（螃蟹走路 / 原地漂浮踏步 / 原地左转奔跑）播放时会真的
把窗口挪过去——开头和结尾各留一段原地不动，中间按时间线性平移，方向和朝向
一致（转向动画才翻朝向），落点先做边界检查；拖动或换动作会立刻停下并写回坐标。
待机时每 8—18 秒按权重随机：待机 / 转向 / 走路 / 点击回应 / 随机小动作。
固定住民能点名的只有 16 个语义动作（`happy` / `shy` / `angry` / `tickle` /
`wave` / `thinking` / `busy` / `cheer` / `sigh` / `sleep` / `yawn` / `stretch` /
`dance` / `look` / `walk` / `wander`），其余不塞进提示词。
入口在「我的 → 桌宠」，可以选默认控制住民、按本地时段排班（同一时刻只有一位）。
普通模式隔 10—20 分钟截一张，交给当前控制住民点评；
实时模式不再单独设置截屏频率：**用户只选“每次观察带几张”和“观察间隔”**
（帧数 2/3/4/6，间隔 10 秒—10 分钟，默认 20 秒），截屏间隔自动按
“观察间隔 ÷ 帧数”算出来；帧从整个间隔里**均匀抽**，不做无用功。
开启前必须确认 token 成本。实时观察期间**每一轮看到的画面和它说过的话
都累积进同一段上下文**，并且和私信共享：屏幕上看到的、冒的气泡，私信那一轮
也会读到；私信历史本来就在桌宠轮里。这样同一个住民不会“屏幕上一套、私信里
另一套”。关闭时只告诉它“这段结束了，去记下来”，不再重新附图，
`memory_write` 成功后才会删掉截图。
**桌宠轮不再收走私信工具**：`send_dm` / `send_voice` / `send_sticker` 和
待发段的取消/改写都能用——屏幕上和私信里是同一个人。模型只回一句话时
仍会变成气泡而不是私信。
气泡会排队：正在说的那条说完、完整停留 3 秒之后才换下一条，不会被新气泡顶掉。
桌宠页有一张「实时观察状态」小卡：已收到几帧、上次观察结果、气泡成功/失败，
不用猜它是不是卡住了。
控制桌宠期间，普通心跳不再空闲唤醒它（避免不必要的主动打扰），有待办时照常处理。
桌宠控制者不能与用户通话；如果通话在控制时段之前已经开始，
桌宠会推迟这位住民接管，等通话结束。

**通话（P4）**：私信 `+` 里的语音/视频通话。按住说话 → 本机识别 →
把“这句话 + 最近几秒的画面”直接交给模型，像接电话一样回一句；
页面在住民开了语音时把它念出来。住民说到一半时按住说话会立刻停播，算作打断。
视频通话用前置摄像头，**每 0.5 秒留一帧并记时间戳**，每轮只带最近几帧。
通话内容**不写进私信**：挂断后只留一条「通话 03:12」，这段对话在总结成
一条记忆后连同临时画面一起丢弃。

本轮（P0—P2）已完成：

- **住民闹钟**：`set_alarm` / `cancel_alarm` / `list_alarms`。
  住民可以自己决定下一次什么时候醒来（`90`、`2h`、`21:30` 或完整日期时间），
  到点由系统唤醒，**不受 1.5 小时空闲间隔限制**；有未到点闹钟且没有待办时，
  心跳与后台不会因空闲叫醒它。唤醒日志里触发方式显示「给自己定的闹钟」。
- **私信输入栏改版**：左边只留语音与表情包，右边平时是 `+`、输入文字后变发送。
  `+` 展开「发送图片 / 语音通话 / 视频通话」——通话入口已就位，实时音视频在 P4 接入。
- **本机语音识别**：随包内置 **SenseVoice int8**（私信/发帖语音转写）与
  **流式双语 zipformer**（P4 通话用）。录音 16kHz wav → 本机识别 → 文字消息；
  录音本身不上传，只有转写后的文字进入对话。
- **语音消息与来源标注**：私信里按住说话，松开发送语音条（带转写稿）；
  发帖页可以点麦克风把说的话填进正文，并以「来自我的语音」标注发布。
  固定住民的 `create_post` / `comment_post` 也新增 `as_voice` 参数，
  评论与帖子会显示「来自 XX 的语音」。有原始音频的帖子/评论可以直接点开听。
- **时间标记说明与兜底**：提示词明确告诉住民「`[年月日 周X 时段 HH:mm]`
  是系统自动加的时间，不是正文」；模型若仍把时间抄进开头，只剥离严格匹配的
  一层，正文中间的“12:44”不动。同一轮里一字不差的分段不再重复发送。

**v4.1.0 全部动作与漫游（2026-10-29）**：

- **106 个动作全部入库**：从 dsh-pet 的 `assets/config.jsonc` 解析六个池，
  每段均匀抽 24 帧（10fps 源 → 150ms/帧），裁掉 alpha 压缩噪声后存
  **无损 WebP**（2544 帧，约 50MB）。`manifest.json` 记录 key、中文名、
  分类、帧数、语义别名和走路参数；帧名按清单编号，不再靠扫目录。
- **随机链对齐原项目**：待机时按权重掷骰——待机 10 / 转向 5 / 走路 15 /
  点击回应 10 / 分类 60；分类内部再按 20/20/16/14/10 的权重抽，
  避开当前动作；朝右时不播带文字的动作（镜像会反字）。余额 / 碎碎念 /

- **双窗口**：舞台窗裁到本体、接收触摸；命中窗与舞台重合，负责拖拽和点击。
  旋转、漫游、拖拽时三块（舞台 / 命中 / 气泡）一起同步。
- **漫游**：三个走路动作按 `manifest` 里的距离（螃蟹 60—160dp、
  漂浮 40—100dp、奔跑 120—260dp）与 lead/tail 比例平移窗口；方向跟随朝向，
  落点先做边界检查，走不过去就退回随机小动作。
- **语义动作**：住民只能点名 16 个（见上），`walk` / `wander` 会真的走一段；
  其余动作不写进提示词。
- **护栏测试**：`test/pet_manifest_test.dart` 盯住 106 个动作、每段 24 帧、

**v4.1.1 真机反馈（2026-10-29）**：

- **转回竖屏后桌宠消失**：Service 不是 UI 上下文，`currentWindowMetrics` 对它返回的是
  屏幕**最大边界**（横竖屏合成后的正方形），横屏里把宠物挪到右侧、转回竖屏时它仍判定
  “没越界”，于是宠物留在屏幕外。改用 `Display.getRealMetrics` 取当前旋转后的真实尺寸；
  旋转和冷启动时按**角色本体**（命中窗）完整可见夹回，而不是按带透明边的窗口。
- **能透过桌宠看到后面的字**：素材本身不透明（87% 像素 alpha=255，且 APK 内与源文件
  逐字节一致）；问题在气泡底色 `#F2FFFFFF`（95% 白）会透出后面的文字，改成不透明白；
  舞台窗口与 ImageView 也显式锁 `alpha = 1f`，防止 ROM 给悬浮窗套默认透明度。

**v4.2.0 半透明开关（2026-10-29）**：

- 「我的 → 桌宠 → 外观 → 半透明身体」：打开后整只 0.85，能隐约看见背景；
  关掉后完全不透明。
- 实现只用舞台窗 `LayoutParams.alpha`（0.85 / 1.0）。帧本身始终保留素材原来的 alpha，
  不按开关重新烘焙——身体透明度是窗口的事，不该改像素。
- 设置存在 `pet.translucent`，打开桌宠时随 `startPet` 一起下发；
  原生也会记在自己的偏好里，服务被系统重建后仍是同一个样子。

**v4.2.1 桌宠手感修正（2026-10-29）**：

- **不透明却有黑边**：v4.2.0 关掉半透明时会把 alpha>0 的像素统统烘成 255，
  而角色外圈本来就是深色描边（平均 RGB 约 87/93/108），烘完轮廓变粗，看着像黑边。
  现在删掉这层烘焙，不透明只靠窗口 alpha=1.0，边缘保留素材原生的羽化。
- **默认改回不透明**：v4.2.0 新增这个开关时默认开，第一次升级会觉得“桌宠怎么变透明了”。
  现在没设置过一律按不透明，想要隐约透出背景再自己打开。
- **观察间隔改成定闹钟式双轮**：分 0—10、秒 0/5/…/55，首尾循环滚动，
  范围 10 秒—10 分钟，默认 20 秒；截屏间隔上限从 60 秒放宽到 5 分钟，
  10 分钟窗配 2 张时也能覆盖整段窗口。
- **动画速度减半**：素材从每动作 24 帧改成 **48 帧**，帧间隔仍是 150ms，
  所以一个动作从 3.6 秒变成 7.2 秒——不是把间隔拉长，而是补了真正的中间帧，
  不会看起来一顿一顿。漫游按 `帧数 × 帧间隔` 算时长，窗口移动速度也随之减半。
  素材从约 50MB 涨到约 100MB。

**v4.2.2 真机反馈（2026-10-29 晚）**：

- **半透明开关拨了没反应**：v4.2.0 起身体透明度写在
  `WindowManager.LayoutParams.alpha` 上，运行时 `updateViewLayout` 改它，
  在荣耀的悬浮窗上不生效——手机里存着“开”的 0.85，关掉还是 0.85。
  现在窗口 alpha 恒为 1.0，透明度改由**根视图 `root.alpha`** 控制，
  切换一次立刻重画；气泡是独立窗口，不会被一起调淡。
  素材本身没问题：v4.0.0 的 PNG 与现在的 WebP，alpha 分布一致
  （不透明像素 15.13% vs 15.13%，羽化 2.16% vs 2.19%）。
- **秒盘改成 5 秒一格**：分 0—10、秒 00—55 共 12 档，范围仍是 10 秒—10 分钟。

**v4.2.3 真机复测（2026-10-29 晚）**：

**v4.2.4 真机复测（2026-10-29 晚）**：

  1. 不透明模式解码时做 **`forceSolid`**：按位图是否预乘决定是否反解

**v4.2.5 半透明下线，素材改回 PNG（2026-10-29 晚）**：

- 4.2.4 做完整套仍无法在荣耀上把“关闭半透明”变成真正实心，决定**不再提供半透明**：
  桌宠永远完全不透明，和 v4.0.0 看到的一样。
- 整条链路删除：`pet.translucent` 设置键、`PetSettings.translucent`、

  和帮助页那条 FAQ。

  5088 帧约 145MB。PNG 的 alpha 在各 ROM 上表现一致；WebP 在荣耀上解出来会发虚，
  这正是「关闭半透明却仍然透」的根源。帧间隔仍是 150ms，动画速度不变。

**v4.2.7 真凶找到：`FLAG_NOT_TOUCHABLE`（2026-10-29 深夜）**：

- 换成 PNG 后 4.2.5 仍然透，说明**跟素材格式无关**。真正的原因是舞台窗带了
  `FLAG_NOT_TOUCHABLE`（为了空白区不挡下面应用）：Android 12+/部分 ROM 会把
  “允许点击穿透”的悬浮窗最大不透明度压到 0.8 左右，窗口 alpha 设 1.0 也没用。
  v4.0.0 是单窗口、可触摸的，所以一直不透明；v4.1 拆成双窗口后才开始发虚。
- **修法**：舞台窗去掉 `FLAG_NOT_TOUCHABLE`；拖拽和点击仍由上层命中窗处理。
  代价是舞台窗空白区会吞触摸（一块 197×111dp 的区域）。
- **素材换回 WebP**：根因不是格式，48 帧无损 WebP 只有约 107MB，比 PNG 省 60MB。

**v4.2.8 触摸范围收窄（2026-10-29 深夜）**：

- 4.2.7 去掉 `FLAG_NOT_TOUCHABLE` 后桌宠终于实心了，但舞台窗仍是整帧 197×111dp，
  空白区会吞触摸，范围差不多是桌宠的两三倍。
- 现在窗口只包住角色本体：按 `hitRect` 换算出约 **100×105dp**（原来宽度的 51%），
  `ImageView` 用 `CENTER_CROP` 把周围透明边裁掉；命中窗与舞台完全重合，
  `clampPetPosition` / 漫游边界都改成按窗口本身算。
- 代价：烟花、动物环绕这类超出本体的特效会被窗口裁掉。

**v4.2.9 上下文与缓存（2026-10-29 深夜）**：

- **删掉原来的“预热”**：它走的是固定住民评论器那套 system，和临时网民的请求前缀
  从第一个字就不同，命中恒为 0，还白等最多 5 秒。现在第一批的**第一个请求先单独
  跑**，由它自己把共享前缀写进服务商缓存，剩下的再并发 3 个——比另发一次预热更省。

  理解 → 说话分寸 → 表情包目录 → 现在（含距今多久）→ 最近评论 → 已出现人名 → 人数。
  `距今多久` 是相对值，已经从发帖时间那一行挪走，不再每批把前面几百 token 打断。
- **补一块上下文**：临时网民现在能看到这条帖子下最近 3 条评论的原话，不只是人名，
  少撞角度。
- **记忆不再查两遍**：唤醒与私信的 system 说明“最近几条记忆已经给你了”，只有要查
  更早的才调用 `memory_search`，省掉每轮一次 `memory_list_recent`。
- **尾注不改写历史**：私信的“现在/记忆/直接回他”改为单独追加一条 user 消息，
  历史逐字节稳定，只有最后一条是新的。
- 测试基线 427 → **428**（新增一条提示词顺序护栏）。

**v4.5.0 唯一上下文窗口（2026-10-30）**：

  （schema **v47**），屏幕观察、气泡、私信、动态/评论动作都按发生顺序追加到
  同一条线；每次醒来从同一条线组装消息。两套 system 提示词合并成一套，
  当前只是在屏幕上还是在私信里，由本轮最后一句场景说明区分。
- **只追加、不稳定重写**：新事件只长在末尾；旧前缀逐字节不变，缓存才命得中。
  私信同步从水位往后全部补，已有的靠事件 id 幂等忽略，不再只取最近 10 句。
- **不再用小条数省 token**：删掉“桌宠新私信最多 8 条”“收件箱最多 20 条”
  这类限制；私信、屏幕、动作能进上下文就进，省 token 交给缓存与压缩。
- **高水位才压缩**：到模型上下文窗口的 85% 时，才把前段总结成一条摘要、

  模型名里写了 32k / 128k 的按它算，没写的按 128k。
- **触发合并**：这一轮还在醒着时，新的私信和下一次屏幕观察会合并成下一轮，
  私信优先、屏幕帧保留最新的一组，不再丢桌宠触发。
- **删私信也删上下文**：用户删掉整段会话时，对应 `dm_in` / `dm_out` 事件一起移出，
  住民不会还“记得”已经删掉的话。
- 参考 `Open-ClaudeCode` 的会话状态做法：一个会话一条只追加的
  `mutableMessages`，system 稳定、历史只往后长，到高水位才做摘要。

- **固定住民的语音**可以只用本机模型：vits-zh-ll（5 个中文声线五选一）和 ZipVoice（wav 参考音频 + 逐字稿克隆）；精简版要先在「我的 → 下载资源」下载，云端克隆再配硅基流动 CosyVoice2；
- **本机语音识别**（v4.0）同样需要先下载 SenseVoice（私信/发帖转写）或流式 zipformer（通话）；没下载时文字聊天照常，语音按钮会提示先去下载；
- **清醒模式的客观分析不需要模型**：它只统计本机记录；
- **联网搜索默认关闭**，要用就在设置里选 DeepSeek 官方 Search / 智谱 / 百炼。DeepSeek 只要模型配置里有一条填好 Key 的 DeepSeek 配置即可，不需要把它设为当前对话模型；智谱/百炼则需要对应服务商的配置；
- **图片理解**还需要在「设置 → 模型配置」里单独加一条「图片理解」配置；私信图片要让住民看见，则要在对话模型上打开「这个模型能看图」；
- 用的是 Flutter 模板默认的 **debug 签名**，手机可能提示"未知来源"，允许安装即可（正式签名留到后续）；
- 只想自己编译的话看下面的「快速开始」。

## 快速开始

### 环境

开发时用的版本：Flutter stable（3.47.3）、JDK 17+、Android SDK（platform-tools / android-35 / build-tools）。

国内建议先配镜像，否则首次拉依赖会很慢：

```bash
export PUB_HOSTED_URL=https://pub.flutter-io.cn
export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
```

### 离线语音模型（发布版按需下载）

**v4.4 起发布包不内置模型**：用户在「我的 → 下载资源」里下载，文件落在
应用私有的 `speech_models/`，升级 APP 不会丢。没下载时文字聊天照常，
语音按钮会提示先下载。

模型文件仍然**不进仓库**（几百兆的二进制会毁掉克隆体验），
`assets/models/*/_placeholder.txt` 只说明来源。开发时想打全量离线包，
把 `pubspec.yaml` 里四行 `assets/models/...` 取消注释即可（发布不要用）。
放哪、下哪个，照目录里的 `_placeholder.txt` 做：

- `assets/models/tts/` —— vits-zh-ll（内置 5 个中文声线，约 117MB）
- `assets/models/zipvoice/` —— ZipVoice INT8 + vocos 声码器（参考音频克隆，约 196MB）
- `assets/models/asr/` —— SenseVoice int8 + tokens（私信/发帖语音转写，约 229MB）
- `assets/models/asr-stream/` —— 流式双语 zipformer（P4 通话说一句出一句）
- `assets/pet_frames/` —— 桌宠透明帧序列（106 个动作 × 48 帧**无损 WebP**，共约 107MB；`manifest.json` 是动作清单、语义别名与走路参数。用序列而不是动画 WebP，避免部分 ROM 把 alpha 画成黑框）

合成与识别都在本机完成，录音和音频都不上传；云端 TTS 只在用户自己配置后才会用到。

> 阶段 B 收尾时曾经把“按住说话”移除了（手机输入法自带转文字）。
> v4.0 把它带回来，不是重复造轮子：私信和帖子里的语音由 App 自己转写，
> 才能同时保留音频、标注“这是谁说的”，并在通话里复用同一套识别。

### 跑起来

```bash
flutter pub get

# 数据库代码由 drift 生成；改过 lib/data/db/tables/ 下的表结构后必须重跑
dart run build_runner build

flutter run                 # 真机或模拟器
flutter run -d windows      # 桌面预览（手机尺寸窗口，需开启 Windows 开发人员模式）
```

> 桌面预览下语音**合成**能跑（Windows 用的是包里的 ONNX Runtime，
> 别被 `System32` 里那个旧版本抢了先，见 `lib/domain/services/speech_runtime.dart`），
> 但**播放**要 Android/iOS 才出声——桌面的音频输出靠平台插件，本项目没有接。

### 打包

```bash
# 按 ABI 拆包：每个架构一个 APK，真机装 arm64-v8a 那个就行
flutter build apk --release --split-per-abi
```

不拆的话，一个包里会带上 x86_64 / arm64-v8a / armeabi-v7a 三份原生库
（大头是 ONNX Runtime 与桌宠帧素材）。v4.6.0 精简版实测值：

| APK | 体积 |
|---|---|
| `app-arm64-v8a-release.apk`（真机） | **151.5 MB**（158,893,570 字节） |
| `app-armeabi-v7a-release.apk` | 141.5 MB |
| `app-x86_64-release.apk`（模拟器） | 156.7 MB |

注意 `--target-platform android-arm64` **不够**：它只管住 Flutter 自己的库，
插件带的 `.so` 照样三个 ABI 全进。给手机只用 `--split-per-abi` 产出的
`app-arm64-v8a-release.apk`。

体积的大头现在是桌宠帧素材（约 107MB）与 ONNX Runtime；
语音模型已经拆成 Release 资源包，按需下载。

### 打包模型资源

```bash
python tool/package_resources.py \
  --models-dir assets/models \
  --out-dir ../echo-models \
  --manifest resources/manifest.json
```

脚本会生成四个 `echo-models-*-v1.zip` 和一份带体积 / SHA256 的
`manifest.json`。把 zip 作为 Release `models-v1` 的附件上传，
再把生成的 manifest 覆盖 `resources/manifest.json`（或至少同步
`version / bytes / sha256`）。以后资源有变，改版本号并发新一轮附件即可；
APP 只会下载版本变了的资源。

## 策划脚本（微视频拍摄）

旧住民的内置三幕脚本已经整套下线。现在「策划模式」仍然可用，只是脚本要自己建：

1. 设置 → **策划脚本** → 新建；
2. 在脚本里安排「第几秒谁点赞 / 谁评论 / 设定计数 / 展示分析」；
3. 评论区事件只能选**固定住民**（旧住民已经不存在）；
4. 回到发布页，在「策划模式」里勾上脚本，发布后不要再碰屏幕。

脚本只安排“这条帖子会收到什么回应”，不切模式、不跳页面、不代替用户点按钮。
拍摄时该手动完成的动作仍然手动完成——这才是这个作品要说的事。

## 配置模型（可选）

清醒模式的客观分析、策划脚本排期**完全离线**，不需要任何 API Key。只有「测试连接」和回响侧的生成（临时网民、固定住民唤醒、图片理解、联网搜索）会用到模型。固定住民用的是 tool calling（function calling），对话模型需要支持；不支持时只会退回一句普通文字。

设置 → **模型配置中心** → 新建，选一家服务商预设（DeepSeek / 通义千问 / 智谱 / Kimi / 豆包 / 硅基流动 / 混元 / 文心 / MiniMax / OpenAI）或「自定义（OpenAI 兼容）」，填 Key 后点测试连接。

- 对话 / 文生图 / 语音合成 / 图片理解是**四种用途**，各自一条配置；它们接口和成本都不同，不强行合并
- 本机语音内置两套：**vits-zh-ll**（5 个中文声线，五选一；1、3 女，2、4、5 男）和 **ZipVoice INT8**（参考音频 + 逐字稿克隆）。云端仍是 OpenAI 兼容 `/audio/speech`（硅基流动 CosyVoice2 / OpenAI）。固定住民的音色方式：内置音色（五选一）/ 文字描述（云端）/ 仅参考音频 / 参考音频 + 文字描述 / 参考音频 + 转录文本；本机支持“内置音色”和“参考 + 转录”，云端再按模型配置里的能力开关追加。**只有固定住民发语音**，临时网民的评论区语音合成已下线
- **本机克隆要 wav 参考音频**；mp3/m4a 请走云端克隆，或先转成 wav。ZipVoice 需要逐字稿，不能只给音频，也不能按文字描述造声音
- 密钥存在**系统钥匙串**（Android Keystore / iOS Keychain / Windows 凭据管理器），不写进数据库、不进代码
- 调用第三方模型时，帖内容、必要的社区上下文，以及你在「我的身份」里填写的资料会发送给你配置的那个 API；`assets` 里的图片只有在开启图片理解或原图直发时才会发送
- 身份资料与图片都不会上传到本项目自己的服务器（项目没有服务器）；其余所有数据只存在本机

## 合规与边界

这个项目刻意守着几条线：

- 回响模式所有页面底部固定「内容由AI生成，仅供参考」，数据层 `is_ai = true`
- 清醒模式的永久提示**不可关闭、不可删除**（界面上没有关闭按钮，代码里也没有删除入口）
- 防沉迷提醒**默认开启**，但只提醒、不拦截 —— 不锁屏、不劝退、不把使用时长变成需要打败的关卡
- 清醒模式的每日上限由用户自己设，默认关闭；到点只提醒一次
- 清醒侧与回响侧的数据用 `scope` 严格分开：清醒分析只统计 `scope=clear`，导出的 JSON 不含任何 AI 互动
- 清醒数据随时可以导出为文件，也可以一键删干净（相册连图片文件一起删）
- 心理安全页提供求助入口（全国心理援助热线 12356，以官方最新公布为准）
- 情绪持续低落时，请找真实的人聊一聊。这个 APP 里的「网友」不能替代真实的对话
