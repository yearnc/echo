# 回响 Echo

一个**单 App 双模式**的社交媒体模拟器。同一块屏幕，两个世界：

- **回响模式** —— 你发一条帖子，周围会临时聚起一群像真人的网民：有人只看、有人点赞、有人接梗。你也可以自己配置固定住民，他们会自己醒来、用工具决定回不回、发不发帖，并记住你们聊过的事。**这里没有一个真实用户。**
- **清醒模式** —— 关掉所有虚拟反馈，只留**根据本机记录算出来的客观分析**（记录频率 / 互动构成 / AI 占比 / 情绪走向 / 时间分布）、数字关系反思、真实生活相册，以及价值重建练习（价值澄清、真实行动记录）。这里的数字不调用模型，也不评价你。

做这个东西的动机很简单：**「被回应」的感觉是可以被制造的**，而人在多大程度上依赖它，往往要等到它消失时才看得清。这个 APP 想把这件事摆到台面上，让你亲手开关一次。

> 项目背景：思政实践课题《数字时代大学生自我价值感的异化与重建》，同时是一部微电影的核心道具。旧住民的内置三幕脚本已经整套下线；拍摄仍可用「策划脚本」自建事件，见下文。

世界观在 B7 之后换过一次：**去掉了"学校"**。AI 住民不再是一群学生，
而是便利店店员、夜班护士、面馆老板、跑团组织者这样的人——
带学校背景会把他们的身份框死，而这个 App 想说的是"任何社区都可能这样"。

v3.9.0 这一版把“换设备”和“住民的日常”补齐了：

- **数据备份与恢复**：我的 → 数据备份与恢复，导出 `.echobak` 全量文件。
  默认模式用固定派生密钥做 AES-256-GCM（免密码、防篡改）；也可以设密码，
  用 PBKDF2-HMAC-SHA256（12 万次）+ AES-GCM，导入时必须输入同一个。
  导入会覆盖本机全部数据，之前有二次确认。模型密钥仍在系统钥匙串，不进备份。
- **导入旧聊天记录**：固定住民编辑页可以贴一条 DeepSeek 分享链接，
  或粘贴「我：/ AI：」格式的文本；读取后交给这位住民用它自己的模型
  整理成长期记忆（来源标为 `import`，重复导入不会产生重复条目）。
  分享页走 DeepSeek 的 `share/content` 接口，思考过程（THINK）不会写进记忆。
- **唤醒日志与留言**：每次真正醒来记一条（时间、触发方式、持续时长）。
  住民可以用 `check_wake_log` 查自己今天什么时候醒过，用 `leave_note`
  给下一次的自己留一句话；下一轮醒来会先看到这句话和留言时间。
  入口在住民编辑页最下面的「日志」。
- **语音修正**：vits-zh-ll 的 5 个声线按实际听感重新标了性别
  （1、3 女；2、4、5 男）；设置页的「语音」分组下线，发不发语音只看
  住民自己的开关；临时网民的评论区语音合成整套移除，只保留固定住民的
  `send_voice`。本机合成搬进常驻后台 isolate，调用语音时界面不再卡住。
- **「正在打字」**：唤醒结束到分段私信真正发完之间，聊天页顶部会显示
  「正在打字…」，不再让那几秒空白。
- **私信界面**：状态只保留在顶部名字下方；没有状态时不再显示
  「固定住民」四个字，消息流底部那个带头像的「正在思考」气泡已移除。
- **刷帖信息更完整**：`browse_feed` 返回每帖的作者、作者类型、发帖时间、
  话题、赞数、评论数和图片数；**刷到就会留下浏览记录**，用户点开浏览量名单能看到 TA 来过（自己的帖子不算）。
- **能点进帖子看了**：新增 `read_post`——完整正文、赞/评论/浏览数、评论区和楼中楼；
  模型支持看图时**优先附原图**（一次最多 4 张），不支持时只告诉它有几张、不猜内容。
  点进去同样算一次浏览。
- **空闲唤醒 1.5 小时**：没有待办时，固定住民的主动醒来间隔从 3 小时缩短到
  1.5 小时（后台仍受系统 WorkManager 15 分钟最小周期约束）。
- **固定住民侧的三处补强**：后台唤醒改成优先级队列（有待办的先，再按最久没醒排，
  不再总是前三个）；唤醒时会告诉 TA 自己动态收到的赞/评论/浏览，只给信息、由它自己决定
  在不在意；记忆检索对中文按 2—3 字滑窗匹配，整句「上次考试的事」也能查到了。

v3.8.0 把本机语音换成两套模型，都是**离线、随 APK 内置**：

- **内置音色（五选一）→ vits-zh-ll**：5 个中文声线（性别标签在 v3.9 按实际
  听感修正为 1、3 女；2、4、5 男），约 116MB，16kHz；新住民先按住民 id
  稳定分配一个，用户可以在编辑页直接改选。旧 AISHELL-3 已移除。
- **参考音频克隆 → ZipVoice INT8 蒸馏（中英）**：encoder 5.4MB + decoder 125MB +
  vocos 声码器 54MB，24kHz；必须“参考音频 + 逐字稿”，推荐 4 步生成。
  住民没上传参考音频时仍走 vits-zh-ll，两条路互不影响。
- **Audio8 下线**：预设、注册接口、相关说明全部移除。
- 本机克隆目前只接受 **wav** 参考音频（没有为 mp3/m4a 引入解码器）；
  云端克隆仍可用硅基流动 CosyVoice2，接受 mp3/m4a。
- 两套本机模型**共用一个引擎槽**：切模型时先释放旧的，避免手机上同时常驻
  两份大模型导致内存吃紧。

v3.7.0 在 v3.6.4 的基础上把「固定住民像真人一样用这个 App」补完整：

- **后台也过日子**：系统后台任务除了语音，其余工具全部可用——回消息、回评论、
  刷帖子、点赞、发动态、画图都行；没有待办的人按 1.5 小时空闲间隔醒一次，
  APP 长期不开时也不会“读不到你发的帖子”。
- **私信分段可打断**：一次醒来写好的几段话带同一个 `deliveryGroup`，还没到点的段
  是 `pending`。你中途又发一句时，未发段先暂停，下一轮把原话交给住民，
  由它自己用 `cancel_pending_segment` / `rewrite_pending_segment` 决定照发、改写还是算了。
  私信节奏改成 3 秒 / 9 秒 / 15 秒。
- **正在做什么看得见**：聊天页与消息列表显示「正在思考 / 正在搜索 / 正在写回复 /
  正在录语音」等真实状态，不是假打字动画。
- **工具限额可调**：默认 12 轮、30 秒（有语音时 +60 秒），设置里可改。
- **音色方式**：内置音色（五选一）/ 文字描述（云端）/ 仅参考音频 /
  参考音频 + 文字描述 / 参考音频 + 转录文本，按语音模型能力置灰。
- **检查更新**：我的页面查 GitHub Releases，只读公开接口，可直接打开发布页。
- **记忆页重做**：容量进度、来源徽章、归档与恢复都更清楚。
- **老库迁移修复**：v38/v39 用 `alterTable` 重建 `custom_residents`，而 `alterTable`
  用的是**当前**表定义。从更老的库升上来时，v41 才加的 `voice_mode` 还没建，
  重建会报 `no such column`。现在在重建前先补这一列，老库能正常升级
  （已在桌面端一份 10-18 的旧库上实测通过）。

v3.6.4 是一次方向性重构：

- **旧住民整套下线**：阶段 A 从 `assets/personas.json` 播种的 32 位旧住民，
  连同他们的帖子、评论、私信、关系、作息、主页与演示脚本一起删除。
  现在社区只有两类人：**用户配置的固定住民**，和每帖临时生成的**临时网民**。
- **固定住民被当成真人**：平台只给信息和工具，不替它做决定。它自己决定回不回、
  发不发帖、评不评论、用不用语音；平台不再“每帖必到”地把它塞进你的帖子，
  也不再自动替它写“我做过什么”的记忆。
- **语音由模型决定**：`send_voice` 是它的一只手，合成成功才落库，不会先出现
  一行文字再变成语音；失败原因会回到它手里，由它自己改用文字或换句话。
- **关系/关注体系随旧住民一起下线**；固定住民没有“关系等级”，
  只有自己的记忆、收件箱和私信历史。

| 数据备份 | 导出 `.echobak` 全量表快照：默认免密码、AES-256-GCM 防篡改；可选密码（PBKDF2 12 万次）。导入前二次确认，导入后手动通知所有数据流刷新；密钥不进备份 |
| 聊天记录导入 | 固定住民编辑页支持 DeepSeek 分享链接（`share/content` 接口）或粘贴文本；提取 REQUEST/RESPONSE、跳过 THINK；交给住民自己的模型整理成记忆，重复导入按内容去重 |
| 唤醒日志 | 每次醒来记时间/触发方式/持续时长；工具 `check_wake_log` / `leave_note`；下一轮带上上一次留言与时间；编辑页有独立日志页 |
| 联网搜索 | 默认关闭。推荐 DeepSeek 官方 `POST /v1/tools/search`（独立工具 API，直接返回来源）；也支持智谱 `web_search` / 百炼 `enable_search`。搜不到会直说，不拿记忆冒充 |
| 表情包 | 不再带内置素材，全部由用户导入并打标签。临时网民在评论 JSON 里选 `sticker_id`，固定住民走 `list_stickers` / `send_sticker` 工具，**现在会真的发出表情包私信**；评论区可以“图 + 一句话”一起发 |
| 网友头像 | 「头像与表情包」页可以导入自己的图作为**临时网民头像**；导入的图与内置 **110 张**（原有 32 张 + 本地文生图扩充的 78 张）**一起参与挑选**（不是替换关系），同一帖尽量不重复 |
| 我的身份 | 设置里可以填性别、年龄段、职业、城市、兴趣爱好、称呼与自我介绍；这些资料会作为稳定前缀发给所有 AI，让称呼和角度更贴近你 |
| 动作账本 | 副作用统一经 `ActionRegistry` 落库，带幂等键与动作日志；同一句话不会因模型重试发两遍 |
| 分页 | 首页首屏最近 10 条帖子；评论区进入时一次加载全部、固定按最早排序，退出即释放 |
| 通知与删除 | 同一条帖子的多个赞合并成「某某等 N 人赞了你的帖子」；自己发的帖子可以在信息流或详情页删除，评论/待发互动/通知一起收走 |
| 评论 | 评论可以同时发图和一句话，也可以只发表情包；表情包评论也会触发住民回应 |
| 本地优先 | 帖子、记忆、私信、密钥全部本地；调用模型时才把必要上下文发给服务商 |

数据层已到 schema **v42**；测试基线 **387**。
APK 仍使用 Flutter 模板默认的调试签名，只用于侧载测试。

## 快速开始

### 环境

开发时用的版本：Flutter stable（3.47.3）、JDK 17+、Android SDK（platform-tools / android-35 / build-tools）。

国内建议先配镜像，否则首次拉依赖会很慢：

```bash
export PUB_HOSTED_URL=https://pub.flutter-io.cn
export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
```

### 离线语音模型（可选，但语音功能靠它）

住户的语音条用的是随包发布的两套离线**合成**模型，**模型文件不进仓库**
（几百兆的二进制会毁掉克隆体验）。不放也能跑：评论区全是文字，
语音条那个入口不出错、只是不出声。

放哪、下哪个，照目录里的 `_placeholder.txt` 做：

- `assets/models/tts/` —— vits-zh-ll（内置 5 个中文声线，约 117MB）
- `assets/models/zipvoice/` —— ZipVoice INT8 + vocos 声码器（参考音频克隆，约 196MB）

两套都在本机合成，一个字都不上传；云端 TTS 只在用户自己配置后才会用到。

> "按住说话"转文字在阶段 B 收尾时移除了：手机输入法自带这个能力，
> 为它多带 78 MB 的识别模型不划算。

### 跑起来

```bash
flutter pub get

# 数据库代码由 drift 生成；改过 lib/data/db/tables/ 下的表结构后必须重跑
dart run build_runner build

flutter run                 # 真机或模拟器
flutter run -d windows      # 桌面预览（手机尺寸窗口，需开启 Windows 开发人员模式）
```

> 桌面预览下语音**合成**能跑（Windows 用的是包里的 ONNX Runtime，
> 别被 `System32` 里那个旧版本抢了先，见 `lib/domain/services/speech_runtime.dart`），
> 但**播放**要 Android/iOS 才出声——桌面的音频输出靠平台插件，本项目没有接。

### 打包

```bash
# 按 ABI 拆包：每个架构一个 APK，真机装 arm64-v8a 那个就行
flutter build apk --release --split-per-abi
```

不拆的话，一个包里会带上 x86_64 / arm64-v8a / armeabi-v7a 三份原生库
（大头是 ONNX Runtime 与两套离线语音模型）。v3.9.0 的实测值：

| APK | 体积 |
|---|---|
| `app-arm64-v8a-release.apk`（真机） | **308.3 MB**（323,258,798 字节） |
| `app-armeabi-v7a-release.apk` | 298.2 MB |
| `app-x86_64-release.apk`（模拟器） | 313.4 MB |

注意 `--target-platform android-arm64` **不够**：它只管住 Flutter 自己的库，
插件带的 `.so` 照样三个 ABI 全进。给手机只用 `--split-per-abi` 产出的
`app-arm64-v8a-release.apk`。

体积的大头是随包发布的两套离线语音模型（约 313 MB）与 ONNX Runtime；
这两样是语音功能本身，拆不掉。放不下模型时应用照样能跑，评论区只是纯文字。

## 策划脚本（微视频拍摄）

旧住民的内置三幕脚本已经整套下线。现在「策划模式」仍然可用，只是脚本要自己建：

1. 设置 → **策划脚本** → 新建；
2. 在脚本里安排「第几秒谁点赞 / 谁评论 / 设定计数 / 展示分析」；
3. 评论区事件只能选**固定住民**（旧住民已经不存在）；
4. 回到发布页，在「策划模式」里勾上脚本，发布后不要再碰屏幕。

拍摄时该手动完成的动作仍然手动完成——这才是这个作品要说的事。

## 配置模型（可选）

清醒模式的客观分析、策划脚本排期**完全离线**，不需要任何 API Key。只有「测试连接」和回响侧的生成（临时网民、固定住民唤醒、图片理解、联网搜索）会用到模型。固定住民用的是 tool calling（function calling），对话模型需要支持；不支持时只会退回一句普通文字。

设置 → **模型配置中心** → 新建，选一家服务商预设（DeepSeek / 通义千问 / 智谱 / Kimi / 豆包 / 硅基流动 / 混元 / 文心 / MiniMax / OpenAI）或「自定义（OpenAI 兼容）」，填 Key 后点测试连接。

- 对话 / 文生图 / 语音合成 / 图片理解是**四种用途**，各自一条配置；它们接口和成本都不同，不强行合并
- 本机语音内置两套：**vits-zh-ll**（5 个中文声线，五选一；1、3 女，2、4、5 男）和 **ZipVoice INT8**（参考音频 + 逐字稿克隆）。云端仍是 OpenAI 兼容 `/audio/speech`（硅基流动 CosyVoice2 / OpenAI）。固定住民的音色方式：内置音色（五选一）/ 文字描述（云端）/ 仅参考音频 / 参考音频 + 文字描述 / 参考音频 + 转录文本；本机支持“内置音色”和“参考 + 转录”，云端再按模型配置里的能力开关追加。**只有固定住民发语音**，临时网民的评论区语音合成已下线
- **本机克隆要 wav 参考音频**；mp3/m4a 请走云端克隆，或先转成 wav。ZipVoice 需要逐字稿，不能只给音频，也不能按文字描述造声音
- 密钥存在**系统钥匙串**（Android Keystore / iOS Keychain / Windows 凭据管理器），不写进数据库、不进代码
- 调用第三方模型时，帖内容、必要的社区上下文，以及你在「我的身份」里填写的资料会发送给你配置的那个 API；`assets` 里的图片只有在开启图片理解或原图直发时才会发送
- 身份资料与图片都不会上传到本项目自己的服务器（项目没有服务器）；其余所有数据只存在本机

## 合规与边界

这个项目刻意守着几条线：

- 回响模式所有页面底部固定「内容由AI生成，仅供参考」，数据层 `is_ai = true`
- 清醒模式的永久提示**不可关闭、不可删除**（界面上没有关闭按钮，代码里也没有删除入口）
- 防沉迷提醒**默认开启**，但只提醒、不拦截 —— 不锁屏、不劝退、不把使用时长变成需要打败的关卡
- 清醒模式的每日上限由用户自己设，默认关闭；到点只提醒一次
- 清醒侧与回响侧的数据用 `scope` 严格分开：清醒分析只统计 `scope=clear`，导出的 JSON 不含任何 AI 互动
- 清醒数据随时可以导出为文件，也可以一键删干净（相册连图片文件一起删）
- 心理安全页提供求助入口（全国心理援助热线 12356，以官方最新公布为准）
- 情绪持续低落时，请找真实的人聊一聊。这个 APP 里的「网友」不能替代真实的对话
