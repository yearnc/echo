**坑 1：Git Bash 的 GNU tar 会把 `D:/xxx.zip` 当成"远程主机 D"**，报 `tar: Cannot connect to D: resolve failed`（exit 128）。
解法：改用系统自带的 bsdtar —— `/c/Windows/System32/tar.exe -xf "<zip>" -C "<目标>"`，或给 GNU tar 加 `--force-local`。

**坑 2：`sdkmanager` 被 Gradle 自动调用时崩溃**。首次 `flutter build apk --debug` 报：

```
Package 28.2.13676358 not found.
> Process 'command 'D:\Android\SDK\cmdline-tools\latest\bin\sdkmanager.bat'' finished with non-zero exit value -1073740791 (NTSTATUS 0xC0000409)
```

原因：新版 cmdline-tools 里 `sdkmanager` 已被 **Android CLI** 取代（1.0.16261425），只保留一个转发 shim；Gradle 自动装 SDK 组件时调它会 fail-fast 崩溃。
解法：**手动装** Flutter 模板要求的 NDK，绕开自动调用：

```bash
"D:/Android/SDK/cmdline-tools/latest/bin/sdkmanager.bat" --install "ndk;28.2.13676358"
```

（该 NDK 版本来自 `flutter/packages/flutter_tools/gradle/.../FlutterExtension.kt` 里的 `ndkVersion` 默认值。）

**坑 5：`sqlite3` 构建钩子要从 GitHub Releases 下原生库，国内直连超时**

```
Unhandled exception:
By default, this package downloads a pre-compiled SQLite library.
This failed (attepted to download https://github.com/simolus3/sqlite3.dart/releases/download/sqlite3-3.5.2/libsqlite3.arm.android.so).
Original cause: HttpException: 信号灯超时时间已到
```

实测：GitHub 直连 **HTTP 000（超时）**；三个 GitHub 代理全部 200，其中 `gh-proxy.com` 最快（0.77s）。
解法：按 `sqlite3` 官方文档（`doc/hook.md`）用 `url_pattern` 换下载源，写进 `pubspec.yaml` **顶层**（不是 `flutter:` 下面）：

```yaml
hooks:
  user_defines:
    sqlite3:
      source: sqlite3
      url_pattern: "https://gh-proxy.com/https://github.com/simolus3/sqlite3.dart/releases/download/$RELEASE_TAG/$FILENAME"
```

`$RELEASE_TAG` = `sqlite3-3.5.2`，`$FILENAME` = `libsqlite3.arm.android.so` 等，由包自动替换。
**安全性**：`package:sqlite3` 会用 pub.dev 上代码里内嵌的 sha256 校验下载文件，所以走第三方代理不会引入供应链风险。
备选代理：`https://ghfast.top`（2.5s）、`https://ghproxy.net`（7.3s）。全部失效时可改用 `source: source` + 本地 `sqlite3.c` 编译（需要 NDK，本机已装）。

**坑 4（最阴的一个）：Windows 跨盘符导致 Kotlin 增量编译失败**

```
Execution failed for task ':audio_session:compileDebugKotlin'.
> Could not close incremental caches in D:\Project\Echo\build\audio_session\kotlin\...
  Suppressed: java.lang.IllegalArgumentException: this and base files have different roots:
    C:\Users\<用户名>\AppData\Local\Pub\Cache\hosted\pub.flutter-io.cn\audio_session-0.2.4\android\src\main\kotlin\...
    and D:\Project\Echo\android
```

原因：**pub 缓存在 C 盘，项目在 D 盘**。Kotlin 增量编译器要把源文件路径转成相对项目根目录的路径，Windows 上跨盘符无法计算相对路径（`different roots`），保存缓存时断言失败。代码本身完全没问题。
解法：在 `android/gradle.properties` 里关掉 Kotlin 增量编译——

```properties
kotlin.incremental=false
```

本项目 Kotlin 代码只有插件样板，关掉增量对速度影响可忽略。
（另一条路是把 `PUB_CACHE` 也设到 D 盘，但会重新下载全部 pub 包，且影响机器上所有 Dart 项目，故未采用。）

**坑 3：`Android Studio Setup Wizard` 报 "Unable to access Android SDK add-on list"**，且 `Finish` 变灰、组件列表缺 Platform-Tools/Build-Tools。实测 `dl.google.com` 是通的（HTTP 200），属临时抽风；向导里点 Cancel 跳过装 SDK 也行，后续用命令行/Studio 的 SDK Manager 补。

- 官网：https://developer.android.com/studio
- **SDK 路径选 D 盘**，例如 `D:\Android\Sdk`，别塞 C 盘

- Device Manager 里勾 USB 驱动（真机调试需要）
- Android Studio 自带 **JBR（JDK 21/17 系）**，不用再单独装 JDK；装完告诉开发助手路径

### 2. 指向 JDK 与 Android SDK（装完由开发助手执行）

```bash
flutter config --jdk-dir="<Android Studio 安装目录>\jbr"
flutter config --android-sdk="D:\Android\Sdk"
flutter doctor --android-licenses   # 一路 y
```

### 3. Gradle 国内镜像（**首次构建最容易卡死的地方**）

`android/settings.gradle.kts` 的 `pluginManagement.repositories` 和 `dependencyResolutionManagement.repositories` 里，**在 `google()` / `mavenCentral()` 之前**加：

```kotlin
maven { url = uri("https://maven.aliyun.com/repository/public") }
maven { url = uri("https://maven.aliyun.com/repository/google") }
maven { url = uri("https://maven.aliyun.com/repository/gradle-plugin") }
```

`android/gradle/wrapper/gradle-wrapper.properties` 的 `distributionUrl`：**只换域名部分，版本号保持 Flutter 模板原样**

```
# 原：https\://services.gradle.org/distributions/gradle-X.Y-all.zip
# 改：https\://mirrors.cloud.tencent.com/gradle/gradle-X.Y-all.zip
```

> 注意：`FLUTTER_STORAGE_BASE_URL` 只管 Flutter 自己的产物（引擎、gradle wrapper 里的 flutter 部分），**管不到 maven 仓库**，所以这两处必须单独改。

**坑 7：`windows/runner/*.cpp` 里写中文注释会导致构建失败**

```
main.cpp(1,1): error C2220: 以下警告被视为错误
main.cpp(1,1): warning C4819: 该文件包含不能在当前代码页(936)中表示的字符
```

原因：MSVC 在中文代码页（936）下把 UTF-8 源文件按 GBK 解析，非 ASCII 字符触发 C4819；
而 Flutter 的 Windows 模板把警告当错误（C2220）。
解法：**`windows/` 下的 C++ 文件保持纯 ASCII**。需要中文窗口标题时用转义写，例如
`L"\u56DE\u54CD Echo"`（= 回响 Echo）——源码仍是 ASCII，编译无恙。
（想彻底解决可在 CMake 里加 `/utf-8` 编译选项，但保持 ASCII 更省事。）

**坑 6：Windows 桌面预览需要「开发人员模式」**

```
Building with plugins requires symlink support.
Please enable Developer Mode in your system settings. Run  start ms-settings:developers
```

原因：Flutter 在 Windows 上给插件建符号链接，必须开启开发人员模式（注册表
`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AppModelUnlock\AllowDevelopmentWithoutDevLicense`）。
解法：`Win + I` → 系统 → 开发者选项 → 打开「开发人员模式」（需要管理员确认）。
只影响桌面预览，不影响 Android/iOS 打包。

**坑 9：`git push` 报 443 连接失败 / Connection was reset，但 `git ls-remote` 却正常**

现象：`curl https://github.com` 返回 200、`git ls-remote` 也能列出远程提交，
只有 `git push` 反复失败，报：

```
fatal: unable to access 'https://github.com/...': Failed to connect to github.com port 443
fatal: unable to access 'https://github.com/...': Recv failure: Connection was reset
```

原因：小请求（握手、读）能过，**上行推送的数据包被中间设备掐断**，国内网络的常见症状。
HTTP/2 尤其容易被中间盒干扰。
解法：让这一次推送走 HTTP/1.1（用命令行临时参数，**不改全局 git 配置**）：

```bash
git -c http.version=HTTP/1.1 push origin main
```

**坑 8：桌面预览窗口尺寸要用「逻辑像素」，且截图会按逻辑尺寸裁剪**

机器屏幕是 1920×1080 + **125% 缩放**（系统逻辑分辨率 1536×864）。
`Win32Window::Size` 的数值是**逻辑像素**，模板 `Create()` 里会乘缩放系数：
写 `Size(390, 780)` → 实际窗口 488×975 物理像素。
若截图工具按逻辑尺寸（390×780）抓图，就只会拍到窗口左上的 80%，看着像"界面被切掉"，
**其实 APP 布局没问题**。验证方法：抓全屏（会得到 1536×864 逻辑图）再看，窗口是完整的。
