## 二、安装步骤

### 2.1 Android Studio

- 官方下载：https://developer.android.com/studio
- SDK 路径建议选择非系统盘，例如 `<Android SDK 目录>`。
- SDK Manager 中勾选：`Android SDK Platform-Tools`、`Android SDK Build-Tools`、`Android SDK Platform 35`（或更新版本）、`Android SDK Command-line Tools`。
- Device Manager 中安装 USB 驱动（真机调试需要）。
- Android Studio 自带 JBR，无需另行安装 JDK；安装完成后记录其路径。

### 2.2 指向 JDK 与 Android SDK

```bash
flutter config --jdk-dir="<Android Studio 安装目录>\jbr"
flutter config --android-sdk="<Android SDK 目录>"
flutter doctor --android-licenses   # 逐项输入 y 接受
```

### 2.3 Gradle 国内镜像

首次构建最易在此环节受阻。

在 `android/settings.gradle.kts` 的 `pluginManagement.repositories` 与 `dependencyResolutionManagement.repositories` 中，于 `google()` / `mavenCentral()` 之前加入：

```kotlin
maven { url = uri("https://maven.aliyun.com/repository/public") }
maven { url = uri("https://maven.aliyun.com/repository/google") }
maven { url = uri("https://maven.aliyun.com/repository/gradle-plugin") }
```

`android/gradle/wrapper/gradle-wrapper.properties` 中的 `distributionUrl` 仅替换域名，版本号保持 Flutter 模板原值：

```
# 原：https\://services.gradle.org/distributions/gradle-X.Y-all.zip
# 改：https\://mirrors.cloud.tencent.com/gradle/gradle-X.Y-all.zip
```

> 注意：`FLUTTER_STORAGE_BASE_URL` 仅作用于 Flutter 自身产物，不覆盖 Maven 仓库，因此上述两处镜像需单独配置。

## 三、已知问题与处理方案

### 3.1 网络与依赖下载

**问题 1：Git Bash 的 GNU tar 将 `<盘符>:/xxx.zip` 解析为远程主机**

报错：`tar: Cannot connect to D: resolve failed`（exit 128）。

处理：改用系统自带 bsdtar：`/c/Windows/System32/tar.exe -xf "<zip>" -C "<目标>"`，或为 GNU tar 添加 `--force-local`。

**问题 2：`sdkmanager` 被 Gradle 自动调用时崩溃**

首次执行 `flutter build apk --debug` 时出现：

```
Package 28.2.13676358 not found.
> Process 'command '<Android SDK 目录>\cmdline-tools\latest\bin\sdkmanager.bat'' finished with non-zero exit value -1073740791 (NTSTATUS 0xC0000409)
```

原因：新版 cmdline-tools 中 `sdkmanager` 已被 Android CLI（1.0.16261425）取代，仅保留转发 shim；Gradle 自动安装 SDK 组件时调用该 shim 会立即失败。

处理：手动安装 Flutter 模板要求的 NDK，绕开自动调用：

```bash
"<Android SDK 目录>/cmdline-tools/latest/bin/sdkmanager.bat" --install "ndk;28.2.13676358"
```

（该 NDK 版本来自 `flutter/packages/flutter_tools/gradle/.../FlutterExtension.kt` 中的 `ndkVersion` 默认值。）

**问题 3：`sqlite3` 构建钩子从 GitHub Releases 下载原生库超时**

```
Unhandled exception:
By default, this package downloads a pre-compiled SQLite library.
This failed (attepted to download https://github.com/simolus3/sqlite3.dart/releases/download/sqlite3-3.5.2/libsqlite3.arm.android.so).
Original cause: HttpException: 信号灯超时时间已到
```

实测：GitHub 直连 HTTP 000（超时）；三个 GitHub 代理均返回 200，其中 `gh-proxy.com` 最快（0.77s）。

处理：按 `sqlite3` 官方文档（`doc/hook.md`）使用 `url_pattern` 替换下载源，配置写在 `pubspec.yaml` **顶层**（不是 `flutter:` 下）：

```yaml
hooks:
  user_defines:
    sqlite3:
      source: sqlite3
      url_pattern: "https://gh-proxy.com/https://github.com/simolus3/sqlite3.dart/releases/download/$RELEASE_TAG/$FILENAME"
```

`$RELEASE_TAG` 为 `sqlite3-3.5.2`，`$FILENAME` 为 `libsqlite3.arm.android.so` 等，由包自动替换。

安全性：`package:sqlite3` 会校验 pub.dev 内嵌的 SHA256，第三方代理不会引入供应链风险。

备选代理：`https://ghfast.top`（2.5s）、`https://ghproxy.net`（7.3s）。全部失效时可改用 `source: source` 配合本地 `sqlite3.c` 编译（需要 NDK）。

**问题 4：`git push` 报 443 连接失败，但 `git ls-remote` 正常**

现象：`curl https://github.com` 返回 200，`git ls-remote` 可列出远程提交，仅 `git push` 反复失败：

```
fatal: unable to access 'https://github.com/...': Failed to connect to github.com port 443
fatal: unable to access 'https://github.com/...': Recv failure: Connection was reset
```

原因：小请求可通过，上行推送数据包被中间设备中断；HTTP/2 尤其容易受影响。

处理：本次推送临时改用 HTTP/1.1，不修改全局配置：

```bash
git -c http.version=HTTP/1.1 push origin main
```

### 3.2 构建工具链

**问题 5：Windows 跨盘符导致 Kotlin 增量编译失败**

```
Execution failed for task ':audio_session:compileDebugKotlin'.
> Could not close incremental caches in <项目目录>\build\audio_session\kotlin\...
  Suppressed: java.lang.IllegalArgumentException: this and base files have different roots:
    C:\Users\<用户名>\AppData\Local\Pub\Cache\hosted\pub.flutter-io.cn\audio_session-0.2.4\android\src\main\kotlin\...
    and <项目目录>\android
```

原因：pub 缓存位于 C 盘、项目位于 D 盘。Kotlin 增量编译器需要将源文件路径转换为相对项目根目录的路径，Windows 下跨盘符无法计算相对路径（`different roots`），保存缓存时断言失败。代码本身无问题。

处理：在 `android/gradle.properties` 中关闭 Kotlin 增量编译：

```properties
kotlin.incremental=false
```

本项目 Kotlin 代码仅包含插件样板，关闭增量对构建速度影响可忽略。

备选方案：将 `PUB_CACHE` 也设置到 D 盘，但会导致全部 pub 包重新下载，并影响本机所有 Dart 项目，故未采用。

**问题 6：`windows/runner/*.cpp` 中的中文注释导致构建失败**

```
main.cpp(1,1): error C2220: 以下警告被视为错误
main.cpp(1,1): warning C4819: 该文件包含不能在当前代码页(936)中表示的字符
```

原因：MSVC 在中文代码页（936）下按 GBK 解析 UTF-8 源文件，非 ASCII 字符触发 C4819；Flutter 的 Windows 模板将警告视为错误（C2220）。

处理：`windows/` 下的 C++ 文件保持纯 ASCII。需要中文窗口标题时使用转义，例如 `L"\u56DE\u54CD Echo"`（即“回响 Echo”），源文件仍为 ASCII。

备选方案：在 CMake 中增加 `/utf-8` 编译选项；保持 ASCII 更简单。

**问题 7：Windows 桌面预览需要“开发人员模式”**

```
Building with plugins requires symlink support.
Please enable Developer Mode in your system settings. Run  start ms-settings:developers
```

原因：Flutter 在 Windows 上为插件创建符号链接，需要开启开发人员模式（注册表 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AppModelUnlock\AllowDevelopmentWithoutDevLicense`）。

处理：`Win + I` → 系统 → 开发者选项 → 开启“开发人员模式”（需要管理员确认）。仅影响桌面预览，不影响 Android/iOS 打包。

**问题 8：`Android Studio Setup Wizard` 报 “Unable to access Android SDK add-on list”**

现象：`Finish` 按钮变灰，组件列表缺少 Platform-Tools / Build-Tools；实测 `dl.google.com` 可访问（HTTP 200），属临时服务异常。

处理：在向导中选择 Cancel 跳过 SDK 安装，后续通过命令行或 Studio 的 SDK Manager 补齐。

### 3.3 设备与界面适配

**问题 9：荣耀/华为手机 `adb devices` 为空（HDB 驱动缺失）**

- 症状：手机连接后文件传输正常，但 `adb devices` 无输出；设备管理器中 `HDB Interface` 状态为错误，`ProblemCode = 28`（驱动未安装）。
- 原因：华为/荣耀系列调试口使用自有 HDB 协议，需要厂商驱动。
- 处理方式：
  1. 不安装驱动也可安装 APK：MTP 可用，将 APK 复制到手机 `Download` 目录后手动安装（需允许“安装未知应用”）。桌面侧可通过 Shell COM 复制（`(New-Object -ComObject Shell.Application).NameSpace(17)` → 设备 → 内部存储 → Download → `CopyHere(路径, 16)`）。注意 MTP 上报的 `Size` 可能为 0，不代表复制失败。
  2. 需要 adb（查看日志、`flutter install`）时安装驱动：手机连接后会挂载 “Honor Suite” 虚拟光驱，其中包含驱动安装向导；也可在设备管理器中对 `HDB Interface` 更新驱动。
  3. 另一方案：使用 Android 11+ 的无线调试（开发者选项 → 无线调试 → 使用配对码配对 → `adb pair`）。

**问题 10：Android 15 起强制 edge-to-edge**

- 症状：真机上页面顶部文字与状态栏重叠。
- 原因：`targetSdk` 达到 35 后系统强制边到边，Flutter 的 `Scaffold` body 不会自动为状态栏留白（仅 `AppBar` 会）。
- 处理：页面骨架统一加入 `SafeArea`（上边留白，下边交给 `bottomNavigationBar`）；贴底组件（如合规提示条）应将 `SafeArea` 放在其容器内部，避免系统手势区露出异色。状态栏与手势条图标亮度需通过 `AnnotatedRegion<SystemUiOverlayStyle>` 显式设置。

**问题 11：`flutter_launcher_icons` 对自适应图标前景额外应用 16% inset**

该工具默认假设前景为满幅内容，会再缩放一圈（`adaptive_icon_foreground_inset: 16`）。本项目前景图已按 66.7% 安全区自行排版并留白，需设置 `adaptive_icon_foreground_inset: 0` 关闭默认缩放。

图标源图处理注意两点：

1. 圆角外的白色背景应填充为卡面色，颜色需从图像中采样；使用近似色会在圆角处产生可见接缝。
2. 暗部零星噪点会使 `getbbox()` 扩展到图像边缘，导致符号偏心。应先按色度过滤噪点，再计算包围盒。

**问题 12：桌面预览窗口尺寸使用逻辑像素，截图可能按逻辑尺寸裁剪**

测试机屏幕为 1920×1080、缩放 125%（逻辑分辨率 1536×864）。`Win32Window::Size` 的数值为逻辑像素，模板 `Create()` 会乘以缩放系数：设置 `Size(390, 780)` 实际得到 488×975 物理像素。若截图工具按逻辑尺寸（390×780）截取，只会得到窗口左上部分，容易被误判为界面被裁剪。验证方法：截取全屏（1536×864 逻辑图）确认窗口完整。

## 七、签名现状

`flutter build apk --release` 当前使用 Flutter 模板默认的 debug 签名（`android/app/build.gradle.kts` 中 `signingConfig = signingConfigs.debug`）。因此 release APK 仅支持侧载安装（系统提示“未知来源”）。正式签名需在后续阶段创建 keystore 后配置。
