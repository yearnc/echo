## 2. P0 时间标记

### 现象

私信里出现「一条正常消息 + 一条开头带 `[2026年10月28日 周三 中午 12:44]` 的重复消息」。
发送路径不加前缀，是模型把历史里的时间前缀当成了正文模仿。

### 处理（不做一刀切）

- **时间信息全部保留**：对方消息继续带完整时间前缀；住民自己的历史也保留，
  只额外在提示词里说明：`[年月日 周X 时段 HH:mm]` 是平台自动标注的发送时间，
  不属于消息正文，回复时不要带。
- **输出兜底**：只剥离开头、且严格匹配完整时间格式的**一层**标记；
  正文中间的“12:44”“明天中午”一律不动。
- **同轮去重**：一次醒来里，如果新写的一段和刚发出去的某段一字不差，不再重复发送，
  把原因交回模型（让它自己决定改写或停）。

### 验收

- 构造带时间前缀的历史，模型输出以时间标记开头时被剥离；
- 正文里的时间不被误删；
- 重复分段只落库一次。

## 3. P1 固定住民闹钟

### 目标

固定住民可以`set_alarm` 给自己定一个未来的唤醒时刻，决定系统下一次何时叫醒它；
闹钟**不受** 15 分钟心跳冷却与 1.5 小时空闲间隔限制。

### 规则

- 有**未到点**闹钟、且收件箱没有待办时：心跳与后台任务**不再因空闲唤醒**这位住民。
- 到点：以 `WakeTrigger.alarm` 唤醒，醒来后闹钟置为已触发；
  如果它还有别的未到点闹钟，继续按“有闹钟不空闲唤醒”处理。
- 有待办时，待办优先，闹钟不阻止正常唤醒。
- 闹钟只在**本机**生效；APP 被系统彻底杀掉时，由 WorkManager 的 15 分钟周期兜底，
  不承诺秒级准时（与现有排期一致）。
- 工具：`set_alarm(when, reason)` / `cancel_alarm(alarm_id)` / `list_alarms()`；
  `when` 接受相对分钟（如 `90`）或 `YYYY-MM-DD HH:mm`。
- 上限：每位住民同时最多 5 个未到点闹钟；最短 5 分钟后。
- 唤醒日志 trigger = `alarm`，页面显示「给自己定的闹钟」。

### 数据

`resident_alarms`（schema v44）：
`id / residentId / fireAt / reason / createdAt / firedAt / cancelledAt`。

### 调度落点

- 前台：`app.dart` 的 1 秒心跳里顺带查一次到点闹钟（很轻，只有到点才动作）。
- 后台：`headless_tick.dart` 每轮先处理到点闹钟。
- 唤醒服务的空闲判定：读“是否有未到点闹钟”。

### 验收

- 定了 90 分钟闹钟的住民，心跳不会在 1.5 小时前叫醒它（没有待办时）；
- 到点后正好被闹钟唤醒一次，日志可查；
- 取消 / 过期 / 删除住民后闹钟不再触发。

## 4. P2 私信输入栏

现状：左边图片 + 表情包，右边固定发送按钮。

目标：

```
[表情] [语音] [ 输入框 ] [+ / ↑]
```

- 左边只留**表情包**；表情包左边放**语音**（按住说话）。
- 右边默认显示 `+`；输入框有文字时变成发送按钮；发送中显示转圈。
- 点 `+` 弹出：发送图片 / 语音通话 / 视频通话。
- 通话入口本轮先落地页面与占位（P4 接实时音视频）。

## 5. P2 离线语音识别与语音消息

### 模型（两套都内置）

| 用途 | 模型 | 大致体积 |
|---|---|---|
| 私信 / 发帖语音转写 | sherpa-onnx SenseVoice（int8，中英日韩粤） | ~230MB |
| 通话实时听写 | sherpa-onnx 流式双语 zipformer | 以实际模型为准 |

- 与 TTS 一样随 APK 发布，目录 `assets/models/asr/`、`assets/models/asr-stream/`，
  模型文件不进 git，按 `_placeholder.txt` 放。
- 统一走常驻后台 isolate，录音时界面不卡。

### 用户侧

- **私信**：按住说话 → 录音 → 转写 → 以 `mediaType=voice` 落库
  （`voicePath` 存 wav、`transcript` 存文字）。气泡显示语音条 + 转写，
  住民醒来时看到的是转写文字；模型支持视觉时不额外发音频。
- **发帖 / 评论**：语音转文字后按文字发布，并记录来源；
  UI 上用「来自 XX 的语音」小标签标注，而不是把标签拼进正文。
- 识别失败时提示重录，不静默发空消息。

### 数据

- `posts.speechBy` / `posts.speechDurationMs`
- `user_comments.speechBy` / `user_comments.speechDurationMs`
- `ai_interactions.speechBy`（住民发评论时带来源）
- 私信沿用现有 `mediaType=voice` + `transcript`。

`speechBy` 存 `me` 或住民 id，显示时再取名字，改名不会出现旧名字。

### 住民工具

- `create_post` / `comment_post` 新增可选参数 `as_voice`（布尔）：
  住民把自己写的话标成“语音发的”，气泡/帖子显示语音来源标签；
  它仍然是文字落库，不需要为它额外合成音频。
- `send_voice` 本来就代表住民语音，保持不变。

## 6. P3 桌宠（已实现，待真机验收）

### 6.1 形象

- **只提供一个形象**，素材来自开源桌宠 [dsh-pet](https://github.com/PC2005-cloud/dsh-pet)
  （VP9-alpha `.webm`）。在构建期挑十来个动作（待机、睡、开心、害羞、生气、
  点击回应、走路、思考）转成 Flutter 原生可透明播放的 **APNG**；
  不引入视频插件的透明层 hack。
- 形象**独立于固定住民**：桌宠是“同一只小生物”，
  由当前时段的固定住民“接管”。切换控制者不换皮，只换说话的人设与记忆。

### 6.2 入口（我的页面）

「我的 → 桌宠」：

- 总开关（默认关）。开启时一次要齐三个权限：
  **显示在其他应用上层**、**截取屏幕**（MediaProjection）、**通知**（前台服务常驻通知）。
- 默认控制住民（下拉选一位）。
- 时段分配表：可添加多段，如 `00:00—08:00 大肥鱼`、`08:00—22:00 另一位`；
  不在任何时段时用默认控制住民。同一时刻**只能有一位**控制者。
- 截屏频率：0.5s / 1s（仅实时模式）。
- 实时模式开关（默认关），旁注成本提示。
- 「立即暂停」与「结束桌宠」。

### 6.3 普通模式（默认）

- 桌宠待在屏幕边缘：呼吸、走动、被戳有反应、偶尔冒一句气泡。
- 每隔一段随机时间（默认 10—20 分钟）截**一张**图，交给当前控制住民点评；
  它可以用 `pet_say` 说一句，或什么都不做。
- 运行时长计入唤醒日志；只允许写**一条简短记忆**（例如“下午看见他在写代码”），
  不把截图累积进常驻上下文。

### 6.4 实时模式

- 开启前弹确认：持续截屏 + 原图发给模型，**会消耗大量 token**。
- 按 0.5s / 1s 连续截屏，按时间戳命名存在会话临时目录；
  每次唤醒附最近若干张原图（滑动窗口，超出部分只保留摘要）。
- 持续唤醒当前控制住民；它可以用 `pet_say` / `pet_react` 实时回应。
- 关闭时：控制住民先把这段时间**总结成记忆**并 `memory_write`；
  **写入成功后才**删除截图文件与临时上下文；失败则保留并提示重试。
- 状态栏常驻前台服务通知，随时可停。

### 6.5 住民可控的接口

| 工具 | 作用 |
|---|---|
| `pet_status` | 桌宠是否运行、当前控制者、模式、剩余配额 |
| `pet_say` | 冒一句气泡（可选表情动作） |
| `pet_react` | 播放指定动作/表情 |
| `pet_look` | 主动请求截一张图（普通模式） |
| `pet_request_watch` | 请求进入实时模式 → 生成**待用户确认**的请求，用户点同意才生效 |
| `pet_sleep` | 缩成一团、暂停打扰 |
| `pet_note` | 写一条简短观察记忆（不做长上下文） |

### 6.6 权限（Android）

- `SYSTEM_ALERT_WINDOW`（悬浮窗，需跳系统设置授权）
- `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MEDIA_PROJECTION`
- `POST_NOTIFICATIONS`（已有）
- `CAMERA` / `RECORD_AUDIO`（P4 通话与 P2 语音需要）
- MediaProjection 每次会话都要用户确认（Android 14+ 限制），
  桌宠重启或进程被杀后需要重新授权，不能静默续期。

### 6.7 隐私边界

- 截屏只在用户授权且桌宠运行时发生；锁屏、通知栏、密码输入场景默认跳过。
- 图片只发给用户在模型配置里指定的服务商；本地临时文件在会话结束（或总结成功后）删除。
- 「我的 → 桌宠」里能一键停止并清空临时截图。

## 7. P4 私信内通话（已实现，待真机验收）

- 私信 `+` → 语音通话 / 视频通话。
- 语音通话：按住说话 → 流式 ASR → 交给住民 → 文字或 TTS 回复。
- 视频通话：前置摄像头小窗（`camera` 插件），可选每 0.5/1s 取一帧，
  与用户这句话的时间戳一起发给住民（原图）；不是屏幕截屏。
- 住民说话中用户按下说话键：**立即停止播放**，丢弃未播音频；
  已生成未播的文本标记为“被打断”，下一轮告诉住民“对方打断了你”。
- 用户可选「住民只发文字」，此时只做 ASR，不做 TTS。
- 开始通话前显示 token 提醒；通话结束写一条会话记忆。

## 9. 风险

- **截屏授权与厂商 ROM**：MediaProjection 在部分国产系统上会被省电策略掐掉；
  必须保底「随时可停 + 通知常驻」，不承诺后台永久存活。
- **APK 体积**：两套 ASR + 两套 TTS 会让安装包继续变大；继续按 ABI 拆包发布。
- **token 成本**：实时模式必须默认关、开启前确认、关闭时总结后清图。
- **隐私**：截屏是最敏感的能力，宁可少做，也不能做“默认开启、静默续期”。

## 11. v4.1.1 / v4.2.0 真机修正（2026-10-29）

- **旋转后跑出屏幕**：`Service` 不是 UI 上下文，`currentWindowMetrics` 对它返回**最大边界**
  （横竖屏合成），横屏挪到右侧回竖屏仍判定"没越界"。改用 `Display.getRealMetrics`；
  旋转/冷启动按**命中窗（角色本体）**整只收进屏幕（舞台窗左右各约 45dp 透明边，
  只夹窗口不够）；拖拽松手仍允许半贴边。旋转后立即收一次、350ms 再补一次。
- **半透明身体**：`pet.translucent`（默认开）→ 舞台窗 `alpha` 0.85 / 1.0；
  关掉时解码帧再做一次 `forceOpaque`（alpha>0→255）兜住 ROM 的 WebP alpha 发虚；
  切换清帧缓存重解。UI 在「我的 → 桌宠 → 外观」。
  **（v4.2.5 起整套下线，见第 12 节——真正的根因是 `FLAG_NOT_TOUCHABLE`。）**

## 12. v4.2.1—v4.2.8 收官（2026-10-29 深夜）

- **动画速度**：106 个动作从 24 帧重抽为 **48 帧**（帧间隔仍 150ms，单动作 7.2 秒），
  漫游时长按 `帧数 × 帧间隔` 自动翻倍、移动速度减半。素材 5088 帧无损 WebP，约 107MB。
- **观察间隔**：双轮循环滚轮（分 0—10、秒 0—55，5 秒一格），范围 10 秒—10 分钟，
  默认 20 秒；截屏间隔上限放宽到 5 分钟，保证 10 分钟窗口能被完整覆盖。
- **桌宠发虚的真根因**：舞台窗带 `FLAG_NOT_TOUCHABLE`，Android 12+/部分 ROM 会把
  “允许点击穿透”的悬浮窗最大不透明度压到 0.8 左右，窗口 alpha 设 1.0 也无效。
  v4.0.0 是单窗口、可触摸的所以实心；v4.1 拆双窗口后开始发虚。
  **修法**：舞台窗去掉该 flag，拖拽/点击仍走上层命中窗。
- **半透明下线**：不再提供 `pet.translucent`；桌宠固定完全不透明，相关 UI / 通道 / 烘焙全部删除。
- **触摸范围**：舞台窗从整帧 197×111dp 裁到角色本体约 **100×105dp**，
  `ImageView` 用 `CENTER_CROP` 去掉透明边；命中窗与舞台完全重合，
  旋转与漫游边界都按窗口本身算。代价：超出本体的特效会被裁掉。
- 发布：commit `d1e3938`、`f950753`，Release v4.2.8（arm64 APK 764,115,605 字节）。
