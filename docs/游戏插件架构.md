# 回响 Echo · 声明式游戏插件架构（v50）

这份文档写给想给「游戏」页做插件的人。

Echo 不执行远程代码，也不会在手机里跑 Node/Python。插件就是一**份 JSON**：
它声明游戏的状态、可以执行的操作、每个操作怎么改状态、什么时候结束。
APP 用本地解释器读取这份 JSON，所以装好之后完全离线，也不需要额外服务。

> 想放 GitHub 仓库也可以：仓库根目录放 `echo-game.json`，用户在
> 「游戏 → 上传游戏」粘贴仓库链接即可。国内直连失败时会自动尝试
> `gh-proxy.com` / `ghfast.top` / `ghproxy.net` 镜像。

## 1. 清单格式

```json
{
  "schema": "echo.game.v1",
  "id": "word_duel",
  "name": "词语对决",
  "description": "两个人轮流猜词，先猜中三个的赢。",
  "min_players": 2,
  "max_players": 2,
  "initial_state": {
    "score": 0,
    "turn": "user",
    "log": []
  },
  "state_fields": [
    { "key": "score", "label": "得分", "type": "number" },
    { "key": "turn", "label": "轮到谁", "type": "text" }
  ],
  "tools": [
    {
      "name": "guess",
      "description": "猜一个词",
      "parameters": {
        "type": "object",
        "properties": {
          "word": { "type": "string" }
        },
        "required": ["word"]
      },
      "effects": [
        { "op": "append_log", "template": "你猜了「{word}」" },
        { "op": "inc", "path": "score", "by": 1 }
      ],
      "finish_when": { "path": "score", "op": "gte", "value": 3 },
      "result": "你先猜中三个，赢了。"
    }
  ]
}
```

### 必填字段

| 字段 | 说明 |
|---|---|
| `schema` | 固定 `echo.game.v1` |
| `id` | 小写字母开头，只含小写字母/数字/下划线，3—32 字符；不能和 `gomoku` / `xiangqi` / `werewolf` 重名 |
| `name` | 游戏名，最多 40 字 |
| `initial_state` | 一个 JSON 对象，游戏开始时复制它 |
| `tools` | 1—30 个操作 |

### 可选字段

| 字段 | 默认 | 说明 |
|---|---|---|
| `description` | 空 | 游戏简介 |
| `min_players` | 1 | 含用户在内的人数，1—9 |
| `max_players` | 1 | 含用户在内的人数，1—9 |
| `state_fields` | 空 | 对局页要显示哪些状态；`type` 可为 `text` / `number` / `bool` |

## 2. 工具（tools）

每个工具在模型那里会变成 `echo_<插件id>_<工具名>`，参数里自动补一个
`match_id`。用户在对局页看到的是同名按钮（按参数弹表单）。

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 小写字母开头，2—32 字符；和插件 id 拼成 `echo_<id>_<name>` 后不超过 64 字符 |
| `description` | 否 | 给模型和用户看的一句话 |
| `parameters` | 否 | 标准 JSON Schema；缺省为空对象 |
| `effects` | 是 | 1—多个效果，按顺序执行 |
| `when` | 否 | 条件数组；不满足时工具不出现在目录里，也不允许执行 |
| `finish_when` | 否 | 执行完这一步后检查；满足就结束整局 |
| `result` | 否 | 结束时显示的结果文案 |

### 效果（effects）

| `op` | 字段 | 说明 |
|---|---|---|
| `set` | `path`, `value` | 把某个路径设为值 |
| `inc` | `path`, `by` | 数字加 `by`（不是数字按 0 算） |
| `append_log` | `template` | 往 `state.log` 追加一行 |
| `set_result` | `template` | 写入 `state._result`，可作为结果的兜底 |

`path` 用点号访问嵌套对象，例如 `player.hp`。

`template` 支持两种占位：

- `{参数名}`：本次调用传进来的参数；
- `{state.路径}`：当前状态里的值。

### 条件（when / finish_when）

```json
{ "path": "score", "op": "gte", "value": 3 }
```

`op` 支持：

| op | 含义 |
|---|---|
| `eq` / `neq` | 按字符串比较相等/不等 |
| `gte` / `lte` | 按数字比较 |
| `truthy` / `falsy` | 非空/非零/非 false |

## 3. 状态与日志

- `initial_state` 会被深拷贝，每个对局各玩各的。
- 插件自己可以把任意字段放进 `log` 数组，对局页会显示最近几条；
  `append_log` 就是往这里追加。
- 整份状态会随对局保存在本地数据库的 `game_states` 里，APP 被杀掉
  再回来还能接着玩。
- 不要在状态里放图片、密钥或大段二进制；插件清单上限 1MB。

## 4. 安装与更新

1. 把 `echo-game.json` 放在 GitHub 仓库根目录；
2. 在「游戏 → 上传游戏」粘贴 `https://github.com/owner/repo`；
3. APP 下载并校验清单，装好后离线可玩；
4. 同一个 id 再安装会更新；换一个仓库但 id 相同会被拒绝，避免互相覆盖；
5. 在同一个上传面板里可以删除插件。

## 5. 能做到什么、做不到什么

**能做**：文字冒险、猜词、问答、资源管理、回合制选择、简单的多人投票/
状态推进——只要规则能用“状态 + 操作 + 条件”描述。

**不能做**：需要新画面/新动画/原生能力的游戏，或者需要访问网络、文件、
传感器的游戏。那需要改 APP 本身，而不是写插件。

## 6. 安全边界

- 只允许 https 的 GitHub / 常见镜像域名；
- 只下载 JSON，不下载可执行文件；
- 清单 1MB 上限；
- `id` 冲突会被拒绝；
- 解释器只认上面列出的 op，未知 op 会让清单解析失败，不会被执行。
