# 回响 Echo · 声明式游戏插件架构（schema v50）

本文档面向希望为「游戏」页开发插件的开发者。

Echo 不执行远程代码，也不在设备上运行 Node/Python。插件以单份 JSON 清单描述：游戏状态、可执行操作、每个操作对状态的修改，以及结束条件。应用内的本地解释器读取该清单，因此安装后完全离线运行，无需额外服务。

> 插件亦可托管在 GitHub 仓库：在仓库根目录放置 `echo-game.json`，通过「游戏 → 上传游戏」粘贴仓库链接即可安装。直连失败时会自动尝试 `gh-proxy.com` / `ghfast.top` / `ghproxy.net` 镜像。

## 1. 清单格式

```json
{
  "schema": "echo.game.v1",
  "id": "word_duel",
  "name": "词语对决",
  "description": "两人轮流猜词，先猜中三个的一方获胜。",
  "min_players": 2,
  "max_players": 2,
  "initial_state": {
    "score": 0,
    "turn": "user",
    "log": []
  },
  "state_fields": [
    { "key": "score", "label": "得分", "type": "number" },
    { "key": "turn", "label": "轮到谁", "type": "text" }
  ],
  "tools": [
    {
      "name": "guess",
      "description": "猜一个词",
      "parameters": {
        "type": "object",
        "properties": {
          "word": { "type": "string" }
        },
        "required": ["word"]
      },
      "effects": [
        { "op": "append_log", "template": "你猜了「{word}」" },
        { "op": "inc", "path": "score", "by": 1 }
      ],
      "finish_when": { "path": "score", "op": "gte", "value": 3 },
      "result": "你先猜中三个，获胜。"
    }
  ]
}
```

### 必填字段

| 字段 | 说明 |
|---|---|
| `schema` | 固定为 `echo.game.v1` |
| `id` | 小写字母开头，仅含小写字母、数字与下划线，长度 3—32 字符；不得与 `gomoku` / `xiangqi` / `werewolf` 重名 |
| `name` | 游戏名称，最多 40 字 |
| `initial_state` | JSON 对象，对局开始时深拷贝 |
| `tools` | 1—30 个操作 |

### 可选字段

| 字段 | 默认 | 说明 |
|---|---|---|
| `description` | 空 | 游戏简介 |
| `min_players` | 1 | 含当前用户在内的人数，1—9 |
| `max_players` | 1 | 含当前用户在内的人数，1—9 |
| `state_fields` | 空 | 对局页展示的状态字段；`type` 支持 `text` / `number` / `bool` |

## 2. 工具（tools）

每个工具在模型侧映射为 `echo_<插件id>_<工具名>`，参数中自动附加 `match_id`；对局页中呈现为同名按钮（按参数生成表单）。

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 小写字母开头，长度 2—32 字符；与插件 id 拼接后不超过 64 字符 |
| `description` | 否 | 供模型与用户阅读的单句说明 |
| `parameters` | 否 | 标准 JSON Schema；缺省为空对象 |
| `effects` | 是 | 一个或多个效果，按顺序执行 |
| `when` | 否 | 条件数组；不满足时工具不出现在目录中，也不允许执行 |
| `finish_when` | 否 | 执行后检查；满足则结束整局 |
| `result` | 否 | 结束时显示的结果文案 |

### 效果（effects）

| `op` | 字段 | 说明 |
|---|---|---|
| `set` | `path`, `value` | 将指定路径设为给定值 |
| `inc` | `path`, `by` | 数值增加 `by`（非数值按 0 处理） |
| `append_log` | `template` | 向 `state.log` 追加一行 |
| `set_result` | `template` | 写入 `state._result`，作为结果的兜底值 |

`path` 使用点号访问嵌套对象，例如 `player.hp`。

`template` 支持两种占位符：

- `{参数名}`：本次调用传入的参数；
- `{state.路径}`：当前状态中的值。

### 条件（when / finish_when）

```json
{ "path": "score", "op": "gte", "value": 3 }
```

`op` 支持：

| op | 含义 |
|---|---|
| `eq` / `neq` | 按字符串比较相等/不等 |
| `gte` / `lte` | 按数值比较 |
| `truthy` / `falsy` | 非空/非零/非 false |

## 3. 状态与日志

- `initial_state` 会被深拷贝，每局对局状态相互独立。
- 插件可将任意字段写入 `log` 数组，对局页展示最近若干条；`append_log` 即向该数组追加。
- 完整状态随对局保存在本地数据库的 `game_states` 表中，应用进程终止后可继续对局。
- 状态中不得存放图片、密钥或大段二进制数据；插件清单上限为 1MB。

## 4. 安装与更新

1. 将 `echo-game.json` 放置在 GitHub 仓库根目录；
2. 在「游戏 → 上传游戏」中粘贴 `https://github.com/owner/repo`；
3. 应用下载并校验清单，安装后离线运行；
4. 相同 id 再次安装将执行更新；若来源仓库不同，安装会被拒绝，以避免覆盖；
5. 同一上传面板中可删除已安装插件。

## 5. 能力范围

**支持**：文字冒险、猜词、问答、资源管理、回合制选择，以及基于投票或状态推进的简单多人玩法。规则能够用“状态 + 操作 + 条件”描述即可。

**不支持**：需要新画面、新动画或原生能力的游戏，以及需要访问网络、文件系统或传感器的游戏。此类需求需要修改应用本体，无法通过插件实现。

## 6. 安全边界

- 仅允许 https 协议的 GitHub 与常见镜像域名；
- 仅下载 JSON，不下载可执行文件；
- 清单大小上限 1MB；
- `id` 冲突时拒绝安装；
- 解释器仅识别上文列出的 op，未知 op 会导致清单解析失败，不会被执行。
