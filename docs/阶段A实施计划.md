## 1. 阶段 A 范围界定

### 1.1 做（阶段 A 验收范围内的）

- 启动引导页、模式选择页
- **回响模式**：首页信息流（帖子卡片、点赞/评论数、热/新标签）、发布页（图文、话题可选）、帖子详情页、评论区
- **预置 AI 人格**（12 个，程序化头像，JSON 配置）
- **策划模式**（2026-09-13 取代原「演示模式」，见 [§7](#7-策划模式微视频的命脉)）：发帖时挂一个脚本，脚本里的点赞 / 评论 / 切模式 / 展示分析按秒级排期真实发生
- **通知与红点**：通知页 + 底部导航红点 + 本地通知基础
- **合规小字**：所有回响模式页面底部固定「内容由AI生成，仅供参考」；数据层 `is_ai = true`
- **模式切换**：回响 ↔ 清醒 状态机、数据归档/删除、二次确认、冷却期
- **清醒模式**：记录页、发布页、客观分析结果页（预置数据 + 可选真实 API）、设置页、永久提示、价值澄清与真实行动的**简版**
- **模型配置中心**：一键配置主流模型（OpenAI 兼容优先）+ 自定义 + 校验/测试对话 + 密钥加密
- **素材系统（头像 / 表情包）**：内置图片优先、文字头像兜底、用户可上传自定义头像与表情包
- 防沉迷提醒简版、心理安全入口、未成年人年龄门

### 1.2 不做（明确推给阶段 B）

- ❌ AI 住民自主发帖 / 动态 / 关系网 / 互相关注 / 私信 / 热榜 / 话题页 / 校园事件系统
- ❌ 后台精确 0—48 小时调度（A 阶段只做**本地队列 + 冷启动补发 + 前台心跳 + 策划模式秒级排期**，`workmanager` 接入留到 B）
- ❌ TTS/STT 真实语音合成（A 阶段用**预置音频** + 静态波形，`just_audio` 播放）
- ❌ AI 人格专属表情包偏好、AI 发图片评论、进阶数据看板、云端同步、上架合规材料
- ❌ SQLCipher 数据库加密（A 阶段仅 API Key 加密）

## 2. 技术选型（最终确认）

| 层级 | 选型 | 理由 |
|------|------|------|
| 框架 | Flutter stable + Dart 3 | 规划书既定，一套代码 Android/iOS |
| 状态管理 | **Riverpod**（不启用 codegen） | 可测试、依赖注入友好；不用 build_runner 生成，减少构建摩擦 |
| 路由 | go_router | 声明式，支持深链（通知点击跳转） |
| 数据库 | **Drift** + sqlite3_flutter_libs | 类型安全、外键/索引/迁移齐全，契合规划书 §8 |
| 密钥存储 | flutter_secure_storage | 走 Android Keystore |
| 网络 | dio | 拦截器、超时、错误映射成熟 |
| 通知 | flutter_local_notifications | 本地通知，无需服务端 |
| 图片 | image_picker + path_provider | 相册/相机；用户上传的素材存 APP 私有目录；清 EXIF 在 B 阶段做实，A 先留接口 |
| 素材 | 内置 assets + 文件路径 + 文字兜底 | 统一走 `AvatarResolver` / `StickerRepository`，随时可换成真实图片，业务代码零改动 |
| 音频 | just_audio | 播放预置语音条 |
| 时间格式化 | intl + 自写相对时间 | "3分钟前 / 昨天 20:14" |

> **A 阶段调度策略（重要决策）**：不做系统级后台任务，改为
> ①发帖时同步在本地 DB 生成 `pending` 互动队列（0—48h 随机 `scheduled_at`）；策划帖则按脚本排成**秒级** `plan_events`
> ②APP 冷启动/回前台时扫描到期任务并补发
> ③**前台心跳**：1 秒一拍，有策划事件就立即兑现，否则每 30 拍扫一次随机队列
> 这样**零后台限制风险、零服务器成本**，微视频拍摄完全够用；真正的 WorkManager/BGTaskScheduler 放 B 阶段。

## 5. 关键接口（设计初稿）

```dart
// 模式状态机
abstract class ModeController {
  AppMode get current;
  Future<void> switchToClear({bool purgeAI = false});
  Future<void> switchToEcho();                 // 含二次确认 + 年龄门 + 冷却期
}

// 互动调度
abstract class InteractionScheduler {
  Future<void> planForPost(Post post, EchoSettings s); // 生成 0—48h 队列
  Future<void> flushDue();                             // 冷启动/回前台补发
  Future<void> triggerDemoAct(DemoAct act);            // 演示模式一键三幕
}

// 模型网关
abstract class ModelProvider {
  Future<ModelResponse> chat(ChatRequest request);
  Future<bool> validate();
  Future<List<String>> listModels();
}

// 素材（头像 / 表情包：图片优先、文字兜底、支持用户上传）
abstract class AvatarResolver {
  ImageProvider? resolve(String? avatarRef);   // asset: → file: → null（调用方降级为文字头像）
}

abstract class StickerRepository {
  Future<List<Sticker>> list({StickerCategory? category});
  Future<Sticker> importFromPicker();          // 复制进 APP 私有目录 + 入库
  Future<void> delete(String id);              // 软删除；内置素材不可删
}

// 客观分析（清醒模式）
abstract class ObjectiveAnalysisService {
  Future<AnalysisResult> analyze(Post post);    // 预置数据 or 真实 API
}
```

> **实际落地情况（2026-09-13 核对）**：阶段 A 最终**没有抽独立的抽象层**——服务与仓储都是「具体类 + Riverpod Provider」，接口与实现同处。
> 与上文初稿的出入如下，看代码时以这张表为准：
>
> | 初稿 | 实际落地 | 差异 |
> |---|---|---|
> | `ModeController.switchToClear / switchToEcho` | `ModeController.persist(target)` + `ModeSwitchService.switchTo(target)` | 切换规则拆到独立服务；**冷却期砍掉**；二次确认与年龄门在 UI 层 |
> | `InteractionScheduler` | `SchedulerService` | 多出策划队列：`planFromScript` / `flushPlanEvents` / `pendingPlanCount` |
> | `triggerDemoAct(DemoAct)` | 无 | 演示模式已撤，改为发布页勾选脚本（见 [§7](#7-策划模式微视频的命脉)） |
> | `ModelProvider`（`chat` / `validate` / `listModels`） | `ModelProbe.test()` | 阶段 A **只做连通性 / 鉴权 / 模型列表 / 测试对话探测**，不做业务生成（留阶段 B） |
> | `AvatarResolver` / `StickerRepository` | `MediaService` + 头像三级兜底 | 表情包管理页尚未建（见 §6 状态列） |
> | `ObjectiveAnalysisService.analyze` | `AnalysisRepository.findByPost` | 阶段 A 以**预置分析**为主（策划脚本里的五项分析落库后读回） |

## 7. 策划模式（微视频的命脉）

> **2026-09-13 更新**：本节原名「演示模式」，那天被**策划模式**取代（原委见 [§8.3](#83-2026-09-13--撤掉演示模式换成策划模式m4--m5-落地)）。
> 旧设计的本质是"在 APP 里播一段戏"——播放器、时间轴、幕标题、进度条，靠「拍摄模式」把这些藏起来；
> 新设计是"**让一条真帖子按脚本发生**"，脚本只负责排期，屏幕上的东西全部是真的。

前两幕的脚本资产转成内置策划脚本，**不依赖真实 API**，拍摄依然稳定、零成本、可重复：

| 幕 | 内置脚本名 | 脚本里发生什么 |
|---|---|---|
| 第一幕 建立幻觉 | 第一幕 · 天空照 | 第 1.2 秒设定开局赞数 → 住民陆续点赞、评论、一条语音条，热度一路爬到第 60 秒 |
| 第二幕 异化与崩溃 | 第二幕 · 深夜垃圾桶 | 深夜发"垃圾桶"照 → 点赞暴涨 + 那段荒谬千字长评 |
| 第三幕 觉醒与重构 | —— **不需要脚本** | 在清醒模式发同一张天空照：清醒模式不排期，所以"零个自动回应"是默认状态；分析页照旧给出五项客观分析 |

> **2026-09-15**：第三幕的内置脚本已下线。原先它唯一的动作是 `analysis`，
> 而清醒模式的客观分析由分析页直接给出、**根本不读策划事件**，所以在界面上
> 它是个点了没反应的脚本；而清醒模式的发布页又没有策划模式入口，
> 真机实测时一眼就看出来了。它要的"没有回响"，本来就是清醒模式的默认状态。

细节要求：

- 拍摄前在**脚本管理页**把秒级时间点调好；按完发布就不要再碰屏幕，事件会自己发生
- 合规元素照常显示（回响模式底部小字、清醒模式永久提示）——**合规不能演掉**

### 7.2 策划模式的作用域（2026-09-14 收窄）

**它只安排"这条帖子会收到什么回应"**：点赞、评论、营造开局热度的计数设定。
它**不碰 APP 的其他任何状态**——不切模式、不跳页面、不代替用户点按钮。

所以第三幕的「切到清醒模式」「去看客观分析」「去做价值澄清」这几步，
**拍摄时全部由人手动完成**。这不是妥协，而是必须的：脚本代劳的话，
"觉醒"这个动作也就变成演的了，而那正是这部片子要戳破的东西。

被去掉的事件类型（曾经实现过，现已移除）：

| 类型 | 曾经的用途 | 为什么去掉 |
|---|---|---|
| `mode` | 按脚本切换回响/清醒 | 改变 APP 全局状态，超出"帖子会不会有人回应"的范围 |
| `open_values` / `open_actions` | 按脚本跳转到价值澄清 / 真实行动页 | 代替用户点按钮；那两步该是真实操作 |
| `settings_hint` / `confirm_dialog` / `rebuild_guide` / `overlay` / `end_card` / `caption_suggestion` | 拍摄装饰与提示卡 | 策划模式下画面里就是 APP 本身，没有舞台 |

> 唯一保留的"非互动"事件是 `analysis`（展示五项客观分析）。它不改变任何状态，
> 只是给清醒模式提供一段可展示的内容。
>
> **2026-09-15 补记**：事实检查下来，`analysis` 目前**没有任何页面读它**——
> 清醒模式的客观分析由分析页直接给出（阶段 A 是预置文本，阶段 B 才接真实模型）。
> 所以它现在是个空转的事件：写进 `analyses` 表，但界面上看不出来。
> 留着它是给阶段 B 用的；第三幕那个"只挂一条 analysis"的脚本因此已下线（见 §7）。

### 8.3 2026-09-13 · 撤掉演示模式，换成「策划模式」（M4 / M5 落地）

上一节的三条待办这天全部收掉，另外做了一个**方向性的改动**。

**为什么撤演示模式**：旧演示模式自带播放器、时间轴、幕标题、进度条，拍摄时全靠「拍摄模式」把这些藏起来——藏得再好，它的本质仍是"在 APP 里演一段戏"：帖子不是真帖子，画面里始终有个舞台。策划模式换了思路：**脚本不参与播放，只负责排期**。

**策划模式怎么用**：

- 发布页勾选「策划模式」→ 选一个脚本 → 脚本的开局内容（正文 / 图片 / 话题）自动填进发布页，用户还能改
- 发帖瞬间，脚本里的事件全部写成 `plan_events` 的排期，之后由调度器逐条兑现
- `at` 写秒数（`"30"`）或区间（`"30~90"`，区间内随机取一个时刻）；从毫秒时间轴转来的脚本支持小数（`"1.2"`）
- 五类事件：**点赞**（一批 delta 个）、**评论**（文本 / 语音）、**设定数据**（把赞数评论数直接设成某个值，营造"这条已经火了"的开局）、**切换模式**、**展示客观分析**
- 屏幕上没有任何演示 UI，帖子就是一条普通帖子 —— **"拍摄模式"这个概念随之消失**

**心跳分两档**（`lib/app.dart`）：定时器固定 1 秒一拍，每拍只做一次很轻的计数查询，空闲时几乎不花钱。

| 档 | 周期 | 理由 |
|---|---|---|
| 策划排期 | 1 秒 | 脚本写"第 1 秒有点赞"就必须真的第 1 秒跳出来；30 秒粒度会把台词毁掉 |
| 随机排期（普通发帖） | 30 拍 | "陆续有人路过"本来就不精确 |

**内置脚本**：三幕 JSON 没浪费。`BuiltinPlanScripts` 把 `act1~3.json` 转成策划脚本，只保留五类真事件，幕标题 / 解说字幕 / 引导卡这些拍摄装饰一律丢弃；第三幕的 `postRef: act1` 展开成第一幕的开局内容（"同一张照片"是那一幕的关键，必须能直接填进发布页）。内置脚本可改、可复制、**不可删**（手滑之后还得找得回三幕）；管理页支持增删改与恢复内置。

**M4 清醒模式**：模式持久化（重启不丢）、切换二次确认、年龄门、切到清醒时停发队列 + 归档已有虚拟反馈 + 写 `mode_switch_logs` 留痕、切过去后一次性「重建引导」。**冷却期砍掉了** —— 规划书里有，但拦着用户不让切不合理。

**M5 模型中心**：10 家服务商预设（按官方文档核对）+ 自定义 OpenAI 兼容；API Key 存系统钥匙串；支持连通性 / 鉴权 / 模型列表 / 测试对话。

**外观独立切换**：新增 `AppPalette` 统一调色板，明暗由外观设置决定（`auto` 时才跟模式走）——明暗不再被模式绑架。页面颜色是直接读调色板的、不走 `Theme`，所以换板后用 `ValueKey` 让整棵树重建一次。

**顺手修掉的**：通知可跳原帖、底部导航误亮、脚本选择读到空列表、设置页缺返回键。

**数据层**：schema 升到 **v6**，新增 `plan_scripts` / `plan_events` / `model_configs` 三张表（共 13 张）；**默认帖子与用户不再播种**（旧播种内容与新方向冲突）。

**当前基线**：**61 个测试全过**、`flutter analyze` 零问题。

### 8.4 2026-09-14 · 阶段 A 收尾

上一节留下的四件事（防沉迷、心理安全、素材管理、README）加上「§1.1 的做清单」里最后两个没兑现的页面，这一天全部收掉。

**数据层（schema 升到 v7）**：按规划书 §8 补上三张表——`value_clarifications`（价值澄清）、`real_actions`（真实行动）、`addiction_logs`（防沉迷日志）。前两张是价值重建闭环的落点，第三张是防沉迷提醒的依据；`feedback_view_logs` 从建库那天就在，但**一直没有代码写它**，所以防沉迷此前没有判定依据。

**价值澄清 `/values`**：写下「我真正重视的 5 件事」。上限 5 条是**刻意的**——收集愿望不需要上限，排序才需要；用户被迫取舍的那一刻，这个练习才开始工作。支持增删改与上移下移，重排全量落库（最多 5 条，比维护相邻两条交换简单，也不会出现"两条序号一样"的中间态）。

**真实行动 `/actions`**：按运动 / 阅读 / 社交 / 创作 / 其他记录线下行动。记录页顶部「本周」原本是硬编码的 `4 / 5 / 0`，现在接了真实的条数，并去掉了那项没有数据源的"情绪平稳（天）"。同时修掉记录页两个入口——它们此前**都指向分析页**。

**心理安全 `/settings/safety`**：使用情况（本次使用时长 + 最近 30 分钟查看反馈次数）、冷静模式开关、防沉迷提醒开关与阈值滑杆、心理援助入口、一键切清醒。这一页的原则写进了页面文案：**只提供信息与开关，不做拦截**——不锁屏、不劝退、不把使用时长变成需要打败的记录。

**防沉迷提醒**：打开帖子详情 = 查看了一次反馈（只在回响模式计，清醒模式没有反馈可看）。30 分钟窗口内达到阈值（默认 8 次，可调 3—30）提醒一次，**同一窗口内不重复提醒**——连着弹三次只会让人想去关掉这个开关。默认开启。

**冷静模式**：开启后，新发帖的互动排期**整体后移 10 分钟**。反馈不是不来，是不那么快就来——这正是要练的：等待期间不刷新，也过得下去。延迟是平移而不是重排，所以"摊开到 48 小时"的形态不变。

**素材管理 `/settings/stickers`**：内置素材以 `assets/stickers.json` 为准、**不落库**（于是"删掉内置素材"这件事从根上不存在，不需要为它维护软删除状态）；用户导入的走 `image_picker` → 复制进私有目录 → 入库，删除是软删除 + 清磁盘。图片缺失一律降级为名字文字贴片，所以素材还没准备好的阶段这一页也能用。

**策划模式接了两个事件，随后又去掉了**：先是把第三幕脚本里原本就有、但因页面不存在被丢弃的 `open_values` / `open_actions` 接回来（执行入口由 UI 层注入，调度器仍然不知道自己在哪个页面里）；同一天收窄作用域时，又把它们连同更早就有的 `mode`（切模式）一起移除。理由见 [§7.2](#72-策划模式的作用域2026-09-14-收窄)——策划模式只安排"这条帖子会收到什么回应"，不操控 APP 的其他状态。调度器因此瘦了一圈：不再需要注入切模式与开页面的回调。

顺带把脚本管理页的「恢复内置脚本」改成「**重置内置脚本**」：已经播种过的库不会自动拿到新版本脚本（比如多了 `open_values` 的三幕），所以需要一个"刷新回出厂版本"的入口；用户自己复制的副本不受影响，弹窗里说清楚了。

**踩到的坑**：`DateTime.now()` 在 Windows 上的实际精度常常只有毫秒，以时间戳为 id 连续插入会撞主键（`PostRepository` 早就在 id 后缀加了随机数，这次两个新仓储照做，测试里也直接暴露了这个问题）。

### 8.6 2026-09-15（下午）· 真机实测反馈：三处修正 + 去掉第三幕脚本

真机（HONOR，Android 15）装上 release 包之后，人眼一看就抓出三处，加上图标一起处理：

**① 顶部和状态栏重叠**：Android 15 起 **edge-to-edge 是强制的**，页面内容直接画到状态栏底下，而骨架没有留安全区。
`AppShell` 与 `ComplianceFooter` 各加一层 `SafeArea`（只留上边，下边归底部导航自己那个），
Scaffold 底色改成跟着调色板走；同时补上 `AnnotatedRegion<SystemUiOverlayStyle>`——
状态栏与手势条的图标亮度跟着调色板，否则系统是浅色主题时，回响模式的深色底上图标会糊掉看不见。

**② 发布提示说话了**：原来是「已发布。反馈会在 0—48 小时内陆续出现。」/「…脚本开始运行了。」
——机制说明不该出现在用户眼前，收成一句「发布成功」。
同理，帖子详情空评论区那句「反馈会在接下来的 0—48 小时里陆续出现」也去掉了：
画面里该有的是"这个帖子还很安静"，不是一个排期表在报工期。
通知页空态底下那句「互动会在 0—48 小时内陆续出现」同属一类，改成
「有人回应你的时候，这里会有提示」——只说这一页是干什么的，不说互动什么时候来。

**③ 顺带补上合规小字**：回响模式的「内容由AI生成，仅供参考」此前**只挂在帖子详情页**
（`AppShell` 里只挂了清醒模式的永久提示），首页 / 通知 / 我的这些页面根本没有。
README 和规划书都要求它"固定"，现在挂回骨架。

**④ 第三幕脚本下线**：见 [§7](#7-策划模式微视频的命脉)。`restoreBuiltIns` 顺手补了
"清掉已下线的内置脚本"这一步——否则老库里那行永远留在那儿。
返回值也从 `int` 改成 `({int written, int removed})`，脚本页的提示改成"刷新 N 个、下线 N 个"。

**⑤ 应用图标**：换掉了 Flutter 默认图标。源图由 AI 生成（深紫底上一圈圈涟漪，
青色那圈是清醒侧的点缀色），处理时踩了两个坑：原图圆角外是**白底**（直接当图标会在安卓上留白角，
填色必须从图里**采样**，写死近似色会在圆角留一道缝）、暗部**噪点把包围盒撑歪**
（先滤噪点再取框，符号才居中）。产出 `assets/icon/` 两张：整块方形图 + 抠好的透明前景
（占画布 62%，落在自适应图标 66.7% 的安全区里），接 `flutter_launcher_icons`
（前景的默认 16% inset 要关掉，否则符号会小一圈），五个密度 + 自适应图标 + iOS 图标一次生成。

### 8.7 2026-09-15（晚）· 编辑资料 + 把「记录」收敛成一件事

**① 昵称与头像终于能改了**

规划书 §15 的三个阶段清单里都没有"改昵称/头像"这一条，但库里**一直有 `user_profile` 表**
（阶段 A 建表时就在，还播种了昵称字段），只是所有页面都直接读常量「同学」，
从没查过这张表——所以"改不了"不是没排期，是两头没接上。

- 新增 `UserProfile` 模型 + `UserProfileRepository`（单行读写；昵称与头像可以分别更新，
  传空字符串是**有意义**的：清掉昵称 = 回落默认名，清掉头像 = 用文字头像）
- 昵称空值一律走 `displayName` 兜底：老库里那一行是空字符串，界面不能出现没有名字的人
- 新增 `/settings/profile` 编辑页：头像预览 + 「从相册选一张」/「用文字头像」+ 昵称
- 头像复用全项目同一套三级兜底（`asset:` → `file:` → 文字头像），自己选的图进 APP 私有目录，
  **换头像时才删上一张**（没保存就退出不会把旧图删掉）
- 名字改了就到处都变：「我的」页、信息流卡片、帖子详情都改成读 `userProfileProvider`

**②「记录」从两个功能收回成一件事**

实测反馈原话："周报也只记录真实行动这里发布的东西，但是下面的「最近」区域，
只统计发布页发布的东西，这两个功能好像分散了。"

确实是两个世界：周报只数 `real_actions`（真实行动页打的点），「最近」只显示
`posts(scope=clear)`（发布页写的图文）。它们本来就是同一件事的两种记法——
一个能配图、成段，一个带分类、够快——所以：

- 新增 `domain/services/record_timeline.dart`：`buildTimeline()` 把两类合成一条时间线，
  `countEntriesSince()` 数窗口内的条数。**纯逻辑**，所以"怎么合、窗口怎么算"可以直接测
- 记录页「最近」= 合并时间线（图文记录带缩略图，真实行动带分类标签）
- 周报数字 = 两者之和，标签从「真实行动」改成「件你亲手记下的」——它现在已经不是某一个入口的名字了
- 真实行动页顶部的本周数字换成同一个 provider：**同一件事在哪儿看都是同一个数字**
- 顺手补上：记录页的图文记录此前**不显示图片**（只显示正文），现在带缩略图了
- 删掉 `weeklyActionCountProvider` 与 `countActionsSince`（被合并的统计取代，避免留两套口径）
